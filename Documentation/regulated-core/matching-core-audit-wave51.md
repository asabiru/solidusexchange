# Matching Core Internals Audit — Wave 51 — Proposed

- Status: Proposed
- Scope: `packages/matching-core/` internals on main — `engine.mjs` (submission/cancel flow, fill pairing, self-trade policy, seq/fill counters, frozen views), `book.mjs` (price-time ordering), `decimal.mjs` (scaled-decimal parse/format), `instruments.mjs` (registry construction), `deterministic.mjs` (clock and ids), `replay.mjs` (event-stream folding) and `snapshot.mjs` (snapshot shape and restore validation). The package is a pure data-only library: fills carry `posting: "none"` and nothing posts to a ledger, so no money-movement surface exists inside it.
- Production effect: none

Hunt list applied: scaled-decimal edges (trailing zeros, canonical vs exact-scale forms, scale mismatch across instruments, near-bound magnitudes), price-time priority (same-price FIFO, market sweep order, partial-fill remainders, maker/taker fill pairing, self-match through wraparound or book corruption, self-trade timing), `seq` monotonicity (rejected submissions burning `seq`, views leaking future counters), adversarial replay streams (duplicate order ids, fills referencing mismatched instruments or sides, resting events for cancelled orders, wrong-position market rejections), adversarial snapshots (malformed counters, seq/fill collisions on later submissions, v1 shape), input validation asymmetries (`submitOrder` vs `cancelOrder` id shapes, owner forms, instrument registry mutation, injected clocks returning non-integer or backwards times), frozen-view leaks through `bookSnapshot`/`journal`/`snapshot`, and restore-vs-replay divergence.

## Defects found and fixed

1. **Half-applied operation when the injected clock throws (`engine.mjs`).** `stamp()` sampled `clock.now()` lazily at each event emission — deep inside `submitOrder`/`cancelOrder`, after the state mutation feeding that event had already happened. A backwards or non-integer clock therefore threw mid-operation and left the engine half-applied. On `submitOrder` the order was stored in the tracked set before its first emission, so `orderStatus` reported a "resting" order no order-acceptance event ever produced, resubmission of the same id was refused `duplicate_order_id`, and — worst — `snapshot()` serialized the phantom, letting `restoreMatchingEngine` rebuild it into the book as real resting liquidity a live engine never emitted. `cancelOrder` had the mirror image: the book entry was removed and the tracked remainder zeroed before the `cancelled` emission, so a throwing clock silently cancelled the order with no journal record at all. The clock is now read once per operation (`beginOperation`), before any state is touched, and every event of one operation shares that timestamp — a throwing clock fails the whole call atomically with the engine byte-identical to its pre-call state.
2. **Replay folded fills a limit taker could never take (`replay.mjs`).** `foldFill` verified the maker sat at the head of the best level, the fill arithmetic and the maker-then-taker pairing — but never compared the taker's limit to the fill price. A stream claiming a `buy` limited to 90 filled a 95 ask (or a `sell` limited to 92 filled a 90 bid) folded cleanly into book state a live engine cannot reach. The folder now refuses a fill priced outside a limit taker's limit (`invalid event stream: fill price is outside the taker's limit`); market takers carry no limit and are unaffected.
3. **Instrument definitions were re-read after validation (`instruments.mjs`).** `instrumentIndex` validated the caller's definition object and only afterwards copied it — every field was read at least twice, so a getter or Proxy could answer validation with `base_scale: 6` and the registry copy with `base_scale: 0`, silently re-scaling the instrument. Each definition is now copied once up front; the same frozen copy is what is validated and stored.
4. **Snapshots admitted non-exact-scale decimals (`snapshot.mjs`).** `parseEngineSnapshot` required order `price`/`quantity`/`remaining` to be canonical scaled decimals but not exact-scale: `"88"` passed for a `price_scale: 8` instrument where the engine itself always stores `"88.00000000"`. A restored engine then answered `orderStatus` with strings no live engine can produce — a quiet restore-vs-live divergence on precisely the surface the snapshot contract promises byte-identical. The validator now requires each stored decimal to equal the engine's own formatter output at the instrument's scale.

## Verified clean

- **Ordering and pairing.** Level queues are FIFO within a price (`book.mjs` appends in acceptance order; priority comes from level price alone), market orders sweep best-level-outward and stop exactly at the limit boundary, and each fill emits the maker event before the taker event under one sequential `fll_` id. Self-match through counter wraparound or book corruption is unreachable: `order_id` shape plus `duplicate_order_id` keep ids unique and the sweep reads live book state.
- **Self-trade timing.** The owner check runs at the head-of-level comparison inside the sweep — before any quantity moves — so a partially-filled taker's remainder is refused `self_trade` exactly when it reaches its own order, never earlier or later.
- **`seq`/`fill` counters.** `seq` is shared across every event type and only ever increments via `stamp()`; rejected submissions intentionally consume `seq` (documented) but never order ids. `orderStatus`, `bookSnapshot` and `journal()` derive purely from past events — nothing exposes `nextSeq`/`nextFill`.
- **Frozen views.** `bookSnapshot` aggregates and freezes fresh depth records; `journal()`/`snapshot()` deep-freeze what they hand out; mutation attempts throw `TypeError`. No shared-reference path into engine state exists (pinned by test).
- **Adversarial snapshot shapes.** Cyclic/self-referencing input, a `v1` version field (no silent migration), resting lists out of book order, counters below recorded-order floors, market orders carrying a price — all fail closed with `invalid engine snapshot` (pinned by test).
- **Decimal edges.** `isScaledDecimal` pins the canonical form (no exponent, no leading zeros, fraction within scale, 18-digit bound); `parseScaledDecimal`/`formatScaledDecimal` round-trip exactly; quantity/price arithmetic is bigint minor units only. Trailing-zero and negative-zero-ish inputs are refused at the regex; values near the 18-digit bound stay exact.
- **Cancel/submit symmetry.** `cancelOrder` validates instrument and order-id shape up front with the same predicates `submitOrder` uses, and owner validation treats an absent key and an `undefined` value identically.
- **Restore vs replay.** After the exact-scale and limit fixes, restore and replay reach identical book state whenever both validate. The one documented divergence — replay loses `owner` tags because order-acceptance events do not carry them — is a stream-data limitation, not a validator hole: snapshots carry owners, so restored engines keep them.

## Observations (recorded, not defects in this slice)

- Rejected submissions burning `seq` is deliberate — the journal must stay contiguously replayable — and the audit confirms no order id is consumed alongside it.
- `next_seq`/`next_fill` are validated as floors derived from recorded orders (`MIN_EVENTS_PER_STATE`), not by exact recomputation — a looser bound by design, and sufficient for the corruption classes hunted here.
- `fill_id` is bounded by `MAX_FILL_NUMBER` in replay; reaching it needs about 2^53 fills — recorded as theoretical.
- A clock whose `now()` returns a different value on every call previously produced non-decreasing-but-distinct timestamps inside one operation; the README left that unspecified. Semantics are now pinned: one timestamp per operation.

## Test additions

- `packages/matching-core/tests/audit.test.mjs` (12 cases): backwards and non-integer clocks failing submissions before any state is touched; the phantom-order path through `snapshot()` into `restoreMatchingEngine` proven absent; backwards clock on cancel; replay refusing fills outside a limit taker's limit on both sides; getter-mutated instrument definitions read exactly once; caller-list mutation after engine creation changing nothing; exact-scale enforcement on snapshot `price`/`quantity`/`remaining`; negative pins for cyclic snapshot input, `v1` snapshots and view-mutation attempts.
- Every new case fails on main and passes on this branch, except the pinned-clean cases which pass on both by design.
