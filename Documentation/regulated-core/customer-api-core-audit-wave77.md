# Customer-Api Core Audit — Wave 77 — Proposed

- Status: Proposed
- Scope: `packages/customer-api/src/app.mjs` (the dispatcher — route table, query grammar gate, path-param decode, gate order, envelope send), `capabilities.mjs` (capability dictionary and evaluation), `operator.mjs` (roster derivation, queue snapshots, audit feed, subject-360 assembly), `auth.mjs` (minted-token verification, audience binding), `auth-session-store.mjs` (digest-only session storage, per-subject bounds) and the not-yet-line-audited read modules `wallets.mjs`, `notifications.mjs`, `support.mjs`, `auth-sessions.mjs`, `users.mjs`, `profile.mjs`, `kyc.mjs`. Cross-checked against `contract.mjs` (OPERATIONS), `server.mjs` wiring, `postgres-store.mjs` and the api-contracts spec. Everything is dev-only and synthetic — no production paths, no live data, no execution surface exists anywhere.
- Production effect: none

Hunt list applied: route-table completeness vs contract ops and shadow routes; method pins; the uniform query grammar gate; path-param decode safety; capability check before builder invocation (deny-before-work); capability dictionary derivation and domain isolation; operator roster digest domains (the wave-324 class); queue snapshot coherence and kind-scoping; audit source coverage and cursor binding; token verification, expiry, subject binding; session store bounds; per-subject accumulations; the error-envelope send path; hostile ids/params/headers, near-match ids, separator tricks, oversized inputs — run live against the dev server plus raw-socket probes.

## Defects found and fixed

1. **The constructor's wiring check skipped `auditFor` (`app.mjs`).** The `operatorSubjectsDirectory` guard named `subjectsFor`, `subjectFor`, `queueFor` and `queueItemFor` but not `auditFor` — the one method the audit-feed arm calls. A hand-rolled directory lacking it booted cleanly and `GET /operator/audit` then 500'd on the TypeError instead of failing fast at construction like every other missing method (repro'd: the server built and served until the arm threw). `auditFor` joins the check, and three existing hand-rolled stubs in `operator.test.mjs` that the new guard correctly caught were completed — the same miswire class the check exists for.

## Verified clean (with negative pins)

- **Route table ≡ contract ops, no shadows**: every one of the 35 declared `OPERATIONS` has exactly one dispatch arm (diffed member-for-member), every arm checks the evaluated capability set before any directory call, the pipeline ends in the `No dispatch arm` throw added by the wave-325 fixes, and a request that misses every literal and template is the pinned 404 — never a fallthrough 500. All methods are GET-pinned; POST/PUT/PATCH/DELETE/OPTIONS/TRACE/HEAD on served paths all miss.
- **Query grammar gate is uniform**: `queryOperation` admits a query string only on `getOperatorQueue`/`getOperatorAudit` — `?` on any other op, even a bare `?`, is the pinned 404. The two gated ops run strict single-occurrence allowlists (`kind` ∈ kyc|aml|tickets; `cursor` matching `^auc_[0-9a-f]{16}$`): unknown keys, duplicates, wrong case and out-of-enum values all answer 400, and percent-encoded parameter names decode into the same allowlist rather than bypassing it.
- **Path-param decode is single and revalidated**: `{instrument}` alone gets one `decodeURIComponent`, then the decoded value must match `[A-Z0-9]{2,8}/[A-Z0-9]{2,8}` — double-encoded, lowercase, NUL-injected, whitespace, traversal and overlong decodes all 404, and a grammar-valid non-member 404s identically (no existence leak). Every other parameter (`{subjectId}`, `{orderId}`, `{operationId}`, `{screeningId}`, `{kind}`, `{itemId}`) validates its raw segment — encoded forms, case variants, suffixes and `%00` stays literal misses.
- **Deny-before-work is total**: gate order is headers → device-id rule → request-id → metadata arm → client-version/platform → rate limit → bearer verify → `validPrincipal` → audience binding → capability → builder → view validator → `send`. A malformed request 400s before auth, an unauthenticated one 401s before capability, a denied one 403s before any directory call, and a directory-returned drifted view throws 500 rather than serving.
- **Capability machinery fails closed**: both policies are frozen literals; evaluation order is kind → decisions → role-scoped deny; an unknown KYC status throws; `customer.*` and `operator.*` vocabularies never cross (a garbage role gets the role-free subset only — `operator.audit.read` stays out); every capability id the dispatcher's checks name resolves to one its own audience's evaluation can produce — no arm claims an id the dictionary cannot mint.
- **Operator roster is one digest domain**: `operatorRoleFor` is the same `units(subject, "role", N)` draw the admin view echoes — the wave-324 cross-domain defect class is structurally closed. The 24-row roster, per-kind queues and subject-360 blocks all derive from `subject-${index}` digests off the single `QUEUE_SNAPSHOT_MS` as-of instant; `subjectRowIndex` is a bounded linear scan.
- **Queue machinery is kind-scoped and snapshot-coherent**: items pin `qky_|qml_|qtick_` + hex off their own kind; the member detail resolves only within its own kind (a `qky_` id under `aml` is a uniform 404); escalation/assignee/age fields recompute from the same snapshot; the view validator is a verbatim recompute — injected, dropped or reordered items all fail.
- **Audit feed source coverage and cursor binding hold**: entries derive from the roster's queue occupancy (kyc/aml/tickets) plus degrading actions; `auditFor` resolves only minted 32-boundary tokens — forged past-end and non-boundary tokens 404, malformed tokens 400; the feed stays oversight-role gated end to end (non-audit roles get 403 on well-formed cursors, 400 on malformed — the grammar check intentionally precedes the capability gate).
- **Token machinery is fail-closed**: separate HMAC digest domains per audience; fixed-32-byte `timingSafeEqual` comparison; 10-digit epoch expiry with a ≤3600 s TTL bound; forged digests, swapped subjects, expired, over-TTL, truncated and wrong-scheme tokens all 401; customer tokens on operator routes and vice versa 401 (separate digest domains); `validPrincipal` re-validates the verifier's principal (subject grammar, deduped scope grammar, canonical `expiresAt` > now) — a drifting verifier fails closed to 500, never to a served view.
- **Subject binding is structural**: member reads carry no subject selector — a token can only ever read its own views; the session read echoes the bound subject verbatim; near-match ids (uppercase, suffixed, truncated) are uniform 404s.
- **Session store is digest-only and bounded**: `sat_` digest storage, `AUTH_SESSION_MAX_PER_SUBJECT`/`MAX_REVOKED_PER_SUBJECT`/`LIST_LIMIT` caps, lazy expiry eviction, exactly-one-`current`, and the postgres CTEs mirror the memory semantics including the advisory subject lock (wave-62 coverage confirmed still holds).
- **Served read modules are coherence-gated**: wallets pin the fixed three-asset table with scale-exact decimals; notifications recount `unread` from the items; support pins the strict lifecycle prefix, one-TTL expiry and `complaint_acknowledged` mirroring; auth sessions pin the bounded list and single-current rule; users/profile/kyc pin exact key sets, grammars and status coherence. Every arm validates the directory's view before `send` — a fabricated or drifted view 500s rather than serving.
- **Error envelope is uniform and echo-coherent**: every failure answers `{code, message, request_id, details}` with `request_id` echoing the client's `X-Request-Id` header (invalid/absent → freshly minted UUIDv7 echoed in both body and `x-request-id` header); the 400/404 gap statuses reuse the same envelope; `Expect` headers 417, `CONNECT` 404s, client errors 400.
- **Per-subject bounds hold everywhere**: 24-row roster cap, ≤32 audit page, ≤8 sessions, bounded queue items (`QUEUE_MAX_ITEMS = 64`), ≤8 recent-activity entries — no unbounded cache or accumulation anywhere in the served path.
- **Hostile transport inputs stay outside**: 20 kB header values 400 (header limit), 5 kB paths 404, absolute-form request targets 404, `Host` presence+unicity enforced, metrics loopback-only with origin/forwarded-header rejection.

## Observations (recorded, not defects in this slice)

- **`getCustomerSession` and `getCustomerCapabilities` echo without a `valid*View` recompute**: the session read constructs its literal payload from the validated principal and the capabilities read echoes the evaluated set — both bounded by `validPrincipal` and the frozen policy, unlike the sibling views that recompute-gate. Deliberate-by-construction, noted as a hardening-depth asymmetry.
- **Query-grammar parse precedes the capability gate on the two query ops**: a denied caller can distinguish 400-grammar from 403-capability but never learns whether a cursor or kind resolves — the grammar itself is contract-public. Intended ordering.
- **`send()` spreads `extraHeaders` after `BASE_HEADERS`**: internal callers pass only `connection`/`retry-after`/`allow` — none collide with the security headers; a future caller could shadow them, noted as an internal-seam edge.
- **`evaluateOperatorCapabilities({role: undefined})` returns the role-free vocabulary**: pinned semantics for the vocabulary projection; every dispatcher arm passes the derived role so the unscoped call is unreachable from the served path.
- **`authSessionLifecycleDirectory` is built in `server.mjs` but not consumed by HTTP dispatch**: the served auth view is a deterministic projection, not a store-backed read — recorded as the intended dev-only seam.
- **No sealed-envelope production path exists in this package**: the dispatch's "envelope" is the error-body shape; Ed25519 envelope sealing lives in the backoffice BFF (separate trust boundary, out of scope).
- **Host header is presence+unicity checked but value-unvalidated**: loopback dev service, the Host value is never used for routing or URL building — recorded.
- **`decisionReasonCode` replaces only the first `-`**: harmless given the single-dash decision vocabulary; recorded as a latent replace-all edge.
- **Dispatch text names `trades`/`markets`/`sessions` modules that do not exist**: in the repo these surfaces live inside `exchange-orders.mjs` and `auth-sessions.mjs`/`auth-session-store.mjs` — followed the real layout; the wave-76 exchange-orders audit plus this wave's session/read-module coverage closes the area.
