# E2E Chain Arms Adversarial Audit — Wave 70 — Proposed

- Status: Proposed
- Scope: `packages/e2e-dev/tests/operator-chain.test.mjs` and `packages/e2e-dev/tests/miniapp-chain.test.mjs` — the two newest end-to-end arms that spawn the real backoffice BFF and customer-api as subprocesses and verify response envelopes against the live keyset — plus their shared harness `packages/e2e-dev/tests/stack.mjs` (`freePort`, `startService`, `stopService`, `verifyEnvelope`). Everything is dev-only and synthetic — no production paths, no live data.
- Production effect: none

Hunt list applied: mutation-test framing on every arm — for each contract axis (envelope verification strength, cross-layer value identity, fail-closed status and error-code pins, ordering and pagination, subprocess lifecycle hermetics, coverage claims vs reality, flake surfaces) the question was "if the product did this wrong, would the arm go red?". Every defect below was proven green-arm on the mutated product or harness before the fix landed; the mutations were introduced only as proofs and reverted — no product change ships in this slice.

## Defects found and fixed

1. **The e2e envelope oracle had drifted behind the consumer verifier (`stack.mjs` `verifyEnvelope`).** Wave 45 mirrored the key-lifecycle rules (Ed25519 algorithm, retired-key horizon) but the canonical-field rules never crossed: the oracle verified true an envelope attested over an empty `requestId`, a non-canonical `issuedAt`, a signature that was not strict unpadded base64url, or a non-canonical-JSON payload (accessor members, class instances, `undefined` leaves, `-0`, non-finite numbers, nesting past depth 16) — every one a form the consumer `verify()` refuses. Proven failing on the pre-fix harness: a signer mutated to emit `requestId: ""` on every envelope left both arms green. The oracle now enforces the full consumer-side contract (record input, exact key set, `signatureVersion === 1`, non-empty string `requestId`, canonical ISO `issuedAt` round-trip, strict base64url signature, `isCanonicalJsonValue` payload) before the Ed25519 check, and the arms additionally pin `envelope.keyId === keyset.activeKeyId` and the published keyset's own shape (`formatVersion`, `backend`, an active Ed25519 entry under `activeKeyId`).
2. **Token lifetime and forgery were never probed.** Neither arm minted an expired, over-TTL or wrong-key credential, so dropping the expiry check in `auth.mjs` (`expiresAtSeconds <= nowSeconds`) stayed green — proven. Both files now pin the synthetic-token contract edge: a token expired by one second, a token whose TTL exceeds `SYNTHETIC_TOKEN_MAX_TTL_SECONDS` and a well-formed token minted under a different key each answer `401 AUTHENTICATION_REQUIRED` with the `Bearer` challenge.
3. **Only the kyc queue kind traversed its member read (`operator-chain.test.mjs`).** The collection walked all three kinds but the member deep-equals ran on kyc alone — the aml `flags` block and the tickets `subject`/`lastMessageAt`/`otherOpenTickets` block had no e2e traversal. Proven failing: dropping the aml flags mapping kept the arm green. The member read now runs per kind (id grammar `qky_`/`qml_`/`qtick_` each), deep-equal against the live directory detail, plus member↔collection coherence on every shared axis — the same recipe the subject roster already used.
4. **`/bff/activity?limit` was validated but never honored under assertion (`miniapp-chain.test.mjs`).** The query-allowlist test rejected `limit=0` and `limit=bogus`, but nothing bound a served value: a handler silently ignoring `limit` on the degrade path stayed green — proven. The arm now pins `?limit=1` to exactly one entry, `?limit=50` to the full local feed and `?limit=51` to `400 invalid_request`.
5. **`/bff/checks/preview` had no happy-path e2e (`miniapp-chain.test.mjs`).** The route was touched only by the `?bogus` rejection and the outage `503`, so forcing `kycRequired: false` for the gated session stayed green — proven. The arm now pins the preview contract verbatim: `CHK-[0-9A-F]{12}` id, canonical decimal strings (`"10.000000"`, `"0.030000"`, `"10.030000"`), `feeBps: 30`, `ttlSeconds: 259_200` with `expiresAt - issuedAt = ttlSeconds·1000`, `insufficientBalance: true` under the denied wallet read (the same honest-zero rule the quote preview follows), `kycRequired` false for the verified session and true for the gated one, and the distinct `invalid_asset` / `invalid_amount` codes on their two tamper classes.
6. **The declared request-header contract was unprobed upstream.** `x-request-id` / `x-client-version` / `x-platform` ride every upstream call, but no test removed or malformed them — disabling the `x-platform` validation stayed green (proven). Both files now pin absent-and-malformed cases for all three headers → `400 VALIDATION_FAILED` before authn.
7. **A forged session bearer was never tried.** Neither arm presented a well-formed-but-never-minted session cookie, so a store resolving sessions by bearer shape rather than token digest stayed green — proven (first-entry resolution answered 200). Both arms now assert the exact `sbt_<64hex>` / `smt_<64hex>` shape with a never-minted digest answers the uniform `401` of an absent cookie.
8. **Subprocess lifecycle was not hermetic (`stack.mjs`).** `stopService` sent SIGTERM and waited on `exit` with no escalation — a wedged child would hang the suite and leak its bound port into later files; `freePort` probed `:0` then released, leaving a probe-release-bind window a parallel file could steal; and `operator-chain` ran customer-api on the shared loopback rate bucket at the default 60/minute window — a margin borrowed from the route count, not pinned. Fixed: `stopService` escalates to SIGKILL after a bounded wait; `startServiceOnFreePort` retries a bounded number of times on `EADDRINUSE` only; customer-api binds kernel-assigned port 0 and reports it through the ready match (with an explicit rebind on the degrade restart); the operator file pins `CUSTOMER_API_RATE_LIMIT_PER_MINUTE` to the same 5000 the miniapp file already used.

## Verified clean

- **Cross-layer value identity.** Every BFF view is deep-compared to the live synthetic directories (`subjectDetailOf` / `queueItemDetailOf` / `auditFeedOf` / `expected*View` projections that mirror each adapter's field order), never to a re-derived or parsed form — decimals and instants compare as their serialized values, so a canonicalization drift on either side fails. Member coherence checks (subject row ↔ detail, queue item ↔ detail) pin the shared axes verbatim.
- **Fail-closed status+code pins.** Deny paths assert the exact status AND the exact error body (`deniedGet` deep-equals `{ error }`, upstream probes assert `.code`), including the uniform-denial mappings: `404`→`CAPABILITY_DENIED` upstream and `*_not_found` at the BFF, `403`→`capability_denied` / `CAPABILITY_DENIED`, `400`→`invalid_request` / `VALIDATION_FAILED`, `503`→per-route `*_unavailable`. A `500` where `403` is contracted fails the status assert before the body check.
- **Ordering and pagination.** The audit feed deep-equals each whole mapped page against the live directory (newest-first with the feed's own tie-break, byte-for-byte), the page-2 disjointness pin is now joined by page-3 exhaustion to `nextCursor: null` on exactly the remaining entries, and `asOf` is the pinned snapshot instant from the directory — a feed served at request time would fail the deep-equal.
- **Envelope resource binding.** `signedGet` asserts `envelope.resource` equals the exact expected binding per call (`operator-queue:${kind}`, `operator-audit:${cursor}`, `operator-subject:${id}`, `session`), so an envelope attested for resource A can never stand in for B — the signature covers the resource inside the canonical message.
- **Env hygiene.** Every subprocess runs on the `childEnvironment` allowlist (PATH + named vars only): a missing variable fails the service's own config loader at boot (`ready` never matches, the bounded start timeout kills the child and fails the file) instead of silently falling back — and the token keys are fresh-random per run, so stale-env contamination can never mint a valid credential.
- **Timing surfaces.** No sleep-and-hope anywhere: readiness is a stdout-pattern match under a bounded kill-timeout, the degrade arms gate on an awaited `stopService` rather than a timer, and no assertion depends on wall-clock ordering beyond `expiresAt > Date.now()` over a multi-day session TTL.

## Observations (recorded, not defects in this slice)

- `freePort` stays exported for the remaining test files (`boundaries`, `resilience`, `load`, `oidc`, the postgres helpers); `startServiceOnFreePort` is now the preferred spawn helper for any service that takes its port from env — this slice migrates the two audited arms and the `dev-stack` BFF spawn.
- `startServiceOnFreePort` retries only on `EADDRINUSE`; a service that exits before ready for any other reason (bad env, missing dist) still fails immediately with stderr — the retry never masks a real startup defect.
- The `operator-audit:${cursor}` resource binding means the signature attests the page boundary itself, not just the page — a replayed first-page envelope cannot stand for page two.
- The tightened oracle is intentionally asymmetric with the consumer: it asserts the envelope the product emitted, so contract drift now fails the arm even when no real consumer sits in the loop.
- `?limit=51` and `?bogus` land on the shared `invalid_request` while `invalid_asset`/`invalid_amount` are distinct codes — the error-code vocabulary is part of the contract and is pinned per class.
