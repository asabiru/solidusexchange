# Shared Simulator Infrastructure Audit — Wave 73 — Proposed

- Status: Proposed
- Scope: `packages/provider-simulators/src/simulator-core.mjs`, `deterministic.mjs`, `signing.mjs`, `callback-inbox.mjs`, plus `errors.mjs`, `interfaces.mjs`, `canonical-json.mjs` and the `checks.mjs`/`quotes.mjs` surfaces that expose the shared machinery. Every domain simulator inherits these primitives: envelope minting that all consumers verify (the e2e `verifyEnvelope` consumer contract is pinned in wave-70), the deterministic RNG behind every derived id, the webhook callback inbox. A defect here corrupts every oracle at once. Cross-checked against consumer call sites in `miniapp/src/server/` (`kyc.ts`, `address-screening.ts`, `provider-quotes.ts`) and `backoffice/src/server/provider-evidence.ts`. Everything is dev-only and synthetic — no production paths, no live data, no execution surface exists anywhere.
- Production effect: none

Hunt list applied: envelope construction (key sets vs consumer pins, canonical-JSON payload rules, canonical instants, request binding, nonce scope, forbidden fields, collision surfaces); RNG (seed handling, per-draw domain separation, counter wrap, ambient-entropy leaks); shared state machinery (bounds, lifecycle guards, error contract vs consumer mapping, clock injection totality); inbox intake (scope checks, replay dedupe, ordering, caps, malformed handling); cross-module drift (local reimplementations); and adversarial headers/bodies/seed edges/wrong-typed signature fields/unicode canonicalization.

## Defects found and fixed

1. **The inbox transition table was unvalidated and read live (`callback-inbox.mjs`).** `createCallbackInbox` never checked `subjectField`, `initialStatus` or the shape of `transitions`: a string value like `{ submitted: "in_review" }` made the transition check fall to `String.prototype.includes`, so a delivery claiming status `"in"` substring-matched into the listed target and mutated the subject — an invalid lifecycle jump the table never declared (repro'd). Non-string values crashed at intake instead of at construction. The table was also consulted by reference: mutating the caller's object after construction rewrote inbox semantics (repro'd — a post-construction edit admitted a transition the inbox had listed as impossible). The factory now validates the whole configuration at construction and snapshots the transition table into a private frozen structure.
2. **Subject deadlines escaped the epoch domain (`callback-inbox.mjs`).** `openSubject` required only `Number.isSafeInteger`, so `deadline: -1` or `2**53` passed while every other instant input in the package is `assertEpochSeconds`-bounded; a negative deadline silently made every subsequent delivery `late`. The same epoch-domain check now applies (repro'd — `RangeError`).
3. **`assertProviderAdapter` hung forever on a cyclic prototype chain (`interfaces.mjs`).** The boundary walk had no termination check: a Proxy adapter whose `getPrototypeOf` cycles back (or never reaches `Object.prototype`) wedged the check — and with it any suite asserting adapter conformance (repro'd: the probe was killed at five seconds with no return). A visited set plus a 64-level depth cap now fails closed with `TypeError`.
4. **The private-name convention bypassed the money-moving name check (`interfaces.mjs`).** `FORBIDDEN_OPERATION` anchored verbs at the very start of a member name, so `_settle`, `_payout`, `_transfer`, `_withdraw` passed the adapter boundary while exposing exactly the operation class it exists to refuse (repro'd). The check now skips a leading underscore run before the verb test; all-caps constants (`_SETTLE_TIMEOUT_MS`) stay exempt.
5. **Unknown delivery modes silently degraded to normal (`simulator-core.mjs`).** `scheduleTimeline(queue, events, "out-of-order", random)` — a typo'd mode — scheduled every event in order, so a resilience scenario meant to exercise reordering would secretly have tested nothing (repro'd). Modes outside the four declared values now throw `TypeError` before anything is scheduled.
6. **The member directory read `kyc_verified` twice (`checks.mjs`).** `validateMembers` read the field once for the boolean check and again for the stored copy, so an accessor profile could pass validation and store an unvalidated value (repro'd: a `true`-then-`false` getter stored `false`, silently denying a member the config marked verified). The field is now read once and stored verbatim.
7. **The verifier trusted a mutable keyring and an unchecked nonce store (`signing.mjs`).** `createCallbackVerifier` kept the caller's Map by reference, so `ring.set(attackerKeyId, attackerKey)` after construction changed what verifies — contradicting the documented immutable-keyring contract (repro'd end to end: a delivery under the injected key verified true). `nonceStore` was never shape-checked, so a missing `record` exploded mid-request rather than at construction. The verifier now snapshots the ring through `createVerificationKeyring` (re-validating every entry as KeyObjects) and requires `nonceStore.record` up front.
8. **The quote staleness check could be silently disabled (`quotes.mjs`).** `assessQuote` never validated `maxPriceAgeSeconds`: `NaN` made `issued - observed > NaN` always false, so a stale price assessed displayable (repro'd). Anything that is not a non-negative safe integer now throws `RangeError`.
9. **Canonical instants admitted out-of-domain epochs (`simulator-core.mjs`).** `isIsoSeconds` checked only that a value round-trips through `toISOString`, so `"0000-01-01T00:00:00Z"` — a negative epoch — passed while every other instant is `assertEpochSeconds`-bounded. A forged callback carrying a pre-epoch `occurred_at` verified end to end (repro'd). Instants now must land in the same epoch domain.
10. **Registry and queue internals were public and writable (`simulator-core.mjs`).** `IdempotencyRegistry.entries`/`maxEntries` and `DeliveryQueue.pending`/`signer`/`order`/`maxPending` were ordinary public fields: `queue.pending = []` lost already-scheduled attested deliveries and `registry.entries.clear()` made a replayed idempotency key re-run its side effect (repro'd). Both classes now keep state in `#`-private fields; nothing outside the classes relied on the fields.

## Verified clean (with negative pins)

- **Envelope key sets are pinned exactly**: each domain's callback validator runs `exactKeys` — kyc 12 keys, kyt 14, bank 15, checks 18, quote 26 — and every simulator emits exactly that set; signature material lives in headers and never inside the payload. No minted payload carries signature-shaped or extra fields a verifier must refuse.
- **The signing input is unambiguous and replay-tight**: `[scheme, domain, keyId, timestamp, nonce, sha256(body)]` joined on newlines with every field regex-bound and the body hashed; the algorithm is bound to the key id inside the keyring, never taken from headers; canonical base64url is enforced by re-encoding. Two envelopes minted at the same instant never share a nonce (a monotonic draw counter per sign call; repro-pin in tests), and `(event_id, occurred_at)` — the `(request_id, issued_at)` analogue — cannot collide: event ids are 128-bit seeded draws.
- **Canonical JSON rules stay aligned with consumer verifiers**: depth 16, plain-proto only, duplicate keys rejected post-decode, NFC-required strings, strict UTF-8 without BOM, safe integers only, reserialize-equals-received — matching the wave-70 consumer pins (`isCanonicalJsonValue`, `CANONICAL_BASE64URL`).
- **The deterministic RNG leaks nothing**: the seed is domain-separated via `"solidchange-sim-seed-v1"` into an HMAC key, draws increment a counter over `label\ndraw\nblock` (labels cannot contain newlines, so no stream confusion), `int` rejection-samples correctly including the 2^32 span edge, and the boundary check bans `Math.random`/`Date.now`/timers across the package.
- **Id derivation needs no per-type domain separation**: `id(prefix, label)` digests the label alone, but the emitted `prefix_hex` string is itself the lookup key everywhere — different prefixes always produce different full ids, so no cross-type collision exists in practice.
- **The error contract matches consumer mapping**: the `ProviderError` union (`provider_unavailable` retryable, `capacity_exceeded`, `idempotency_conflict`, `invalid_request`, `not_found`, `scenario_not_configured`) is exactly what miniapp/backoffice adapters map (`kyc.ts`, `provider-quotes.ts`, `provider-evidence.ts`, `address-screening.ts`); consumers see no non-`ProviderError` escape on the adapter paths.
- **Inbox machinery is sound**: dedup records are written before late/stale evaluation (bounded per subject by `maxEventIds`), the parked-drain re-checks transitions before applying buffered successors, `discard` forgets a subject's dedup records, `expire` marks non-terminal subjects once past deadline, and every structure is bounded.
- **Cross-module coherence holds**: all five domains inherit `createCallbackSigner` (domain-bound), `DeliveryQueue`, `IdempotencyRegistry`, `snapshotRequest`, `scheduleTimeline` and `toIsoSeconds`; no local reimplementation of envelope minting, RNG or the inbox exists — the OIDC issuer's separate RS256 JWT machinery is deliberate and documented in-package.

## Observations (recorded, not defects in this slice)

- **Nonce records key on the bare nonce**: each domain verifier keeps its own store, so the contract is one store per verifier — sharing one store across domains would conflate replay scopes (the same nonce under a different key id would read as a replay).
- **`IdempotencyRegistry.run` can surface a `JsonError`** (not a `ProviderError`) when handed a non-canonical request directly — unreachable through the adapters, where every field is validated before `run`; recorded as a direct-use contract edge.
- **`isPositiveSequence` caps at 1000**: a subject can never process event 1001 — the cap is what bounds dedup and parked state.
- **OIDC `mintCode` evicts the oldest unexpired pending code at capacity** — bounded, but it diverges from `createNonceStore`'s fail-closed policy: an in-flight login's code can be evicted under flood. Dev-only policy, noted.
- **OIDC uses ambient `randomBytes`** for codes, tokens and keypairs — deliberate non-determinism (auth material is not seed-derived), documented in-package.
- **`emit` consumes a sequence number for `delivery: "none"` scenarios** — harmless because a check's scenario is fixed at creation, so no visible gap ever appears.
- **The keyring snapshot means mid-rotation key additions need a fresh verifier** — this is the documented immutability contract made real.
- **Deadline rejections moved `TypeError` → `RangeError`** under the unified epoch check; `boundary.test.mjs` was repinned for the stronger class.
- **The "(11 keys?)" audit prompt's framing does not match any pin**: sim callback payloads pin at 12/14/15/18 keys per domain (26 for quotes); the 8-key shape is the BFF API envelope verified by e2e `verifyEnvelope` — a different format, not a defect.
- **`checkComment` is validated then dropped** — the `CheckView` contract does not model comments in this slice (intentional).
