# Matching Core Replay and Recovery Audit — Wave 75 — Proposed

- Status: Proposed
- Scope: `packages/matching-core/` recovery machinery on main — `src/replay.mjs` (`replayMatchingEngine`, `replayMatchingJournalStore`, `restoreMatchingEngine`), `src/snapshot.mjs` (`canonicalEngineSnapshot`, `parseEngineSnapshot`, `hydrateEngineState`), and the fold's seam with `src/engine.mjs` and `src/journal-store.mjs`/`src/postgres-journal-store.mjs` (audited in #336/#338/#301). The durable event grammar in `migrations/0002_journal_event_grammar.sql` is in scope where it must mirror the fold.
- Production effect: none

Hunt list applied: replay determinism (replay(journal) ≡ live state, intra-level FIFO after replay, seq/fill counters resumed); the snapshot↔journal seam (tail apply, double-apply, gaps, snapshot ahead/behind/empty/corrupt); journal grammar versus replay grammar divergence in either direction; envelope identity and replay re-journaling; amended/cancelled order reconstruction at the right priority position; snapshot capture atomicity, boundedness and version pinning; failure modes — partial journals, interleaved instruments, self-trade reject events, clock drift inside an operation.

The fold's contract (its JSDoc): a stream is only admissible when it is a prefix the real engine could have emitted — every structural property the live pipeline guarantees is re-verified in the fold. The audit found that contract was checked per event but not per *operation*: streams that interleaved events the live engine emits atomically, or that recorded rejections/restings the live engine could never emit, folded cleanly and produced books a real engine cannot reach.

## Defects found and fixed

1. **The fold interleaved operations the live engine emits atomically (`src/replay.mjs`).** `replayMatchingEngine` validated each event in isolation but tracked nothing about which operation an event belonged to: an order-acceptance event opens an unfinished operation in the live engine — its emitted batch continues with that order's fill pairs and its terminal `resting`, `rejected` or final `filled` — yet the fold let a *second* order's acceptance, `resting`, `cancelled`, `amended` or `rejected` events pass in between. Repro: intake `A(sell 90)`, intake `B(sell 90)`, `resting B`, `resting A` folded into a level queue `[B,A]` that no live stream can produce (live emits `resting A` before B's intake exists); a following fill pair then resolved the swapped head so `B` ended `filled` where every live emission fills `A` first. The fold now tracks the in-flight order (set on order intake and by a priority-losing `amended`, cleared by its `resting`, terminal `rejected`, or final taker fill): while it is set, only that order's fill pairs and resolving event are admissible — any other event is `interleaved event while an order is in flight`, and a stream ending mid-operation is `stream ends mid-operation`.
2. **Timestamps could drift inside an operation (`src/replay.mjs`).** `beginOperation` reads the clock once and stamps every event of the operation with that read, so all events of one live operation share `at`; the fold only pinned global non-decreasing order, so `intake@t1, resting@t2` for one order folded despite never being emittable. Each boundary event now owns the operation's stamp and every mid-operation event must carry it — `timestamp changes inside an operation` — while equal `at` across distinct operations stays legal.
3. **`resting` events were not checked against the book (`src/replay.mjs`).** A taker rests only after its sweep found nothing matchable, but the fold admitted `resting` for an order whose price crossed the current opposite head — a stream claiming a bid at 91 rested on top of an ask at 90 folded, and because the end-of-stream crossed-book check is the only book consistency guard, a later `cancelled` masked the fabrication entirely. `resting` now verifies the resting order does not cross the best opposite head — `resting order would cross the book`.
4. **Terminal rejections were not verified against the live trigger (`src/replay.mjs`).** `self_trade` fired in the fold for different owners, for same-owner orders that never cross, and with an empty opposite book — all states where live fills or rests instead — and `insufficient_liquidity` fired on market takers while makers sat at the best level — live would have matched. The fold now re-checks the live policy's exact trigger: `self_trade` needs the best opposite head present, matchable against the taker's limit, and sharing its owner (ownerless heads and takers cannot self-trade); `insufficient_liquidity` needs a market taker facing an empty opposite side. Otherwise `... rejection is not earned`.
5. **Validation rejections carried unverified echoes (`src/replay.mjs`).** Any `rejected` with a non-terminal reason and grammar-shaped echo fields folded — `duplicate_order_id` for an id never tracked, `order_not_resting` for an order actually resting, `no_change`/`quantity_below_filled` echoing a side the tracked order does not have, `invalid_price` echoing an id that could never reach the price check. Each reason now pins what the failed submission could have echoed: `duplicate_order_id` needs a tracked id; `order_not_resting` needs a valid-pattern id on a non-resting (or untracked) order with the cancel-shape (known instrument, null side) or amend-shape (tracked instrument+side) echo; `no_change`/`quantity_below_filled` need an in-book resting target echoed with its own fields (and below-filled needs something already executed); `invalid_instrument` echoes null, `unknown_instrument` a string outside the registry, `invalid_order_id` a null or non-pattern id, `invalid_side` a valid id on a known instrument (the side itself is unconstrained — it echoes the invalid input); the remaining owner/type/price/quantity reasons echo a valid-pattern id, a known instrument and a valid side. `invalid_order` stays unpinnable beyond shape — it echoes whatever string fields the raw input carried.
6. **The store grammar admitted a timestamp replay refuses (`migrations/0003_journal_event_timestamp.sql`).** `valid_journal_event` bounded `at` by ISO shape regex alone, but PostgreSQL's `timestamptz` cast *normalizes* the ISO end-of-day spelling `'T24:00:00Z'` to the next day instead of rejecting it — so the payload CHECK passed, the row landed, and `load()` returned a payload `fromIsoSeconds` refuses: one stored row that poisons a namespace forever. Every other non-real spelling the regex admits (month 13, April 31, minute 60) already errors on the cast and fails loudly; `T24:00:00Z` is the only silent hole. The recreated function now requires the `at` text to survive the round trip through `timestamptz` unchanged, which covers this and any future cast normalization. `schemaVersion` bumped to 3; source catalog and policy verifiers updated.

## Verified clean

- **Replay determinism on honest streams.** Live journals replay to byte-identical `snapshot()`/`bookSnapshot`/`orderStatus` — the wave-59 mixed scenario (crossed books, partial fills both directions, cancels, validation rejects, self-trade, every amend path, market orders, a second instrument) still folds and snapshots identically; the replayed engine continues `seq` and `fill_id` contiguously (`next event gets max(seq)+1`, fills resume at `lastFill+1`); `journal()` returns the folded stream frozen and byte-identical to live.
- **Intra-level FIFO.** The fold rebuilds resting queues in tracked-order order — itself pinned to live's add/re-queue semantics — so FIFO inside a level is preserved, not just totals; the snapshot's `resting` list must equal the tracked resting set positionally or the round trip fails.
- **Fill pairing.** Maker event then taker event, one sequential `fll_` id, exact arithmetic (`remaining_units - executed === remainder`), maker pinned to the head of the best level, taker limit checked — all re-verified per pair; `filled` must end at zero remainder and `partially_filled` must keep one.
- **Amend reconstruction.** The fold mirrors live's priority rule — price change or quantity increase re-queues at tail (and now correctly marks the order in flight until resolved), a decrease at unchanged price keeps the slot — with `previous_price`/`previous_quantity` pinned to tracked state, `quantity` as total required above the filled part, and no-op amends rejected as not emittable.
- **Journal grammar parity in the strict direction.** Rejected-event field rules in the store grammar (null-or-string echoes, quantity only on the two terminal reasons, per-type key sets, `posting: "none"`, id/owner patterns, decimal shape) mirror the fold's shape checks — a payload violating them is rejected at insert, well before replay sees it.
- **Crossed books and counter correlation.** Snapshots with crossing resting orders fail; `next_seq`/`next_fill`/`last_at` correlate with the recorded orders via the per-state minimum-event floors; `kind`/`version` are pinned exactly, symbol keys are rejected, and non-plain structures are cloned away before validation.
- **Replay purity.** The fold writes nothing to any journal store during validation — `journalStore` is attached only to the finished engine, so replayed events cannot re-emit or re-journal (the reentrancy surface is the engine's own `append`-inside-`finish` path, already guarded in #336).
- **Truncated and partial journals.** A stream missing a terminal event fails (`stream ends mid-operation` now names it explicitly; the snapshot correspondence check caught it before); a truncated fill pair fails inside the pair check; a seq gap, a non-monotonic `at`, or a non-canonical decimal all fail before any state is committed.

## Observations (recorded, not defects in this slice)

- **No snapshot+tail seam exists.** `replayMatchingEngine` requires `seq` from 1 — there is no API to apply `journal[N+1..M]` onto a snapshot taken at `seq=N`, so "snapshot ahead of journal", "double-apply of N", and "gap at N+1" have no surface to pin: snapshot and full-journal-replay are two complete recovery paths, not a composable one. If a tail-apply seam is added, it should validate `first_seq === snapshot.next_seq` exactly.
- **Grammar remains looser than semantics by design.** The store's `valid_journal_event` knows envelope grammar, not engine state: instrument registry membership, exact per-instrument decimal scale, and every "earned" check (crossing, owner match, tracked-order echo) stay the fold's job — a payload can pass storage and still fail replay, which the contract test pins as intended behavior, not a divergence.
- **`invalid_order` rejections are echo-free by construction.** Any string-or-null combination of `order_id`/`instrument`/`side` is emittable (they echo raw input fields), so no per-reason pin applies — the only bound is the grammar's null-or-string shape.
- **Mid-operation `at` equality now enforced; `last_at` stays non-decreasing only.** Two operations may share a second — the fold allows it (live can emit it) — so timestamp order remains a partial order across operations even though it is total inside one.
- **Snapshot capture is synchronous and boundary-consistent.** `snapshot()` reads committed state (`state.nextSeq`/`nextFill`/`lastAt` commit inside `finish` after `append` returns) — a snapshot cannot observe a mid-operation book; the residual risk is a store-visible post-mutation/pre-commit window documented in wave-69, unchanged here.
- **`order_not_resting` echo is ambiguous by shape.** The same reason covers cancel-path (null side, submitted instrument) and amend-path (tracked instrument+side) — the fold admits either emittable combination rather than guessing the call site, which is the only choice that keeps replay strictly inside live-emittable prefixes.
- **Owner presence is still optional.** An order-acceptance event with no `owner` folds fine, and such orders can never earn `self_trade` — matching live, where ownerless orders never self-trade.
