# Customer API Core Machinery Audit — Wave 36 — Proposed

- Status: Proposed
- Scope: `packages/customer-api/src/` core machinery on main — `auth.mjs` (synthetic token verification), `server.mjs` (wiring and listen gate), `app.mjs` (request pipeline), `rate-limit.mjs` (fixed-window limiter), `request-id.mjs` (id generation and echo), `capabilities.mjs` (read/financial evaluation), `observability.mjs` (log and metric surfaces), `config.mjs`, `contract.mjs`, and `wallets.mjs` (synthetic wallet directory). Route-surface conformance was covered by the contract-coverage suite; this wave hunted the injected-dependency and clock edge cases in the machinery itself.
- Production effect: none

Hunt list applied: token verification bypasses (missing algorithm check, unsigned tokens, expired/nbf tolerance, key mixups), capability confusion (verified-KYC bypass, tier downgrade), rate-limit overflow/negative-window/burst-count errors, header injection via request-id echo, response splitting via echoed headers, malformed-input 500s (headers, body, path), unbounded maps, PII/secret leakage in logs or error bodies, timing-sensitive comparisons that should be constant-time.

## Defects found and fixed

1. `createSyntheticTokenVerifier` in `auth.mjs` never checked the clock reading. A non-finite `clock()` (NaN, a non-numeric string, undefined) makes `expiresAtSeconds <= nowSeconds` and `expiresAtSeconds - nowSeconds > maxTtlSeconds` both false, so every token — expired or over-TTL — verified. This is a fail-open expiry bypass on the single check that stands between a minted token and the session/capabilities/wallets routes. `verify` now returns `null` unless `nowSeconds` is finite.
2. `createSyntheticTokenVerifier` also never validated `maxTtlSeconds`. A `NaN`/`Infinity`/non-integer bound silently disabled the TTL ceiling (a forged token could claim any `exp`), and `0` would have rejected every fresh token — the caller had no signal either way. The constructor now throws unless the bound is a positive safe integer, matching the `limit` validation already in the rate limiter.
3. `createFixedWindowRateLimiter` in `rate-limit.mjs` validated only `limit`. `windowMs <= 0` made every new bucket already expired (`now >= resetAt` always true), silently switching the limiter off; `maxKeys = NaN` made `buckets.size >= maxKeys` false forever, removing the bound on the bucket map — an unbounded per-subject Map, exactly the growth class on the hunt list. Both options are now validated as positive safe integers.
4. The same limiter trusted `clock()`. With a non-finite reading a bucket persisted `resetAt: NaN` (never expiring, never pruning) and the 429 path emitted `retry-after: NaN` — a malformed numeric header value. `consume` now fails closed with `{ allowed: false, retryAfterSeconds: ceil(windowMs / 1000) }` when the clock reading is not finite.
5. `generateUuidV7` in `request-id.mjs` called `BigInt(nowMs)` directly, which throws `RangeError` on non-integer or non-finite input (a drifting clock such as `performance.now`, or `NaN`). Every caller — `handle()`, `rejectRaw`, `checkExpectation` — invokes it outside the request pipeline's try/catch, so the throw surfaced as an unhandled rejection instead of a `500 internal_error` envelope. The timestamp is now sanitized (`Math.trunc` of a finite input, `0` otherwise) so id generation cannot throw.
6. `validWalletsView` in `wallets.mjs` enforced only the response *shape* (exact keys, string values) but not the `WalletView` field patterns from `openapi.yaml` (`syn_wal_…`, uppercase asset code, `decimalAmount`). A drifted directory view such as `available: "soon"` was served `200` with a body that violates the declared contract instead of falling into the guard's `500` path. The guard now enforces the three field patterns, and the drifted body answers the `internal_error` envelope without echoing the offending value.

## Verified clean

- Token verification: no algorithm confusion (the format prefix `scdev1.` and subject pattern are pinned before any crypto; no `alg` member exists to confuse), the 64-hex tag is compared with `timingSafeEqual` over fixed-length buffers, `exp`/`nbf` semantics are a single future-expiry+TTL bound, the signing domain string is fixed, and the key is bound at construction (`assertKey` requires 64 lowercase hex chars). Wrong-key tokens verify as `null`.
- Capability evaluation in `capabilities.mjs`: closed KYC-status set (`verified` alone unlocks `wallets.read`), unknown statuses throw rather than evaluate, `kind === "read"` plus empty reasons gates the read capability, and every financial capability is answered with explicit decision objects — no tier downgrade path exists because no tiers exist below the verified check.
- Request pipeline in `app.mjs`: `JSON.stringify` runs before `writeHead`, so response bodies cannot inject header bytes; `errorBody` uses only fixed `ERROR_MESSAGES` and literal call-site strings (no attacker-controlled echo); `collectHeaders`/`singleHeader` refuse multi-valued echoed headers; `x-request-id` is echoed only when it already matches the UUIDv7 pattern, and `generateUuidV7` output is pattern-clean, so no header splitting path exists through the id echo.
- Raw-head handling: `clientError`/`rejectRaw`/`checkExpectation` render fixed status lines and `BASE_HEADERS` only; request-target decoding and header parsing failures map to 400/408/431/417 before routing.
- `server.mjs`: binds the verifier, KYC store, wallet directory and limiter strictly from `config.mjs`; post-listen loopback assertion rechecks the bound address.
- `config.mjs`: refuses `NODE_ENV=production`, loopback hosts are the fixed `{127.0.0.1, ::1}` set, integers are strict-patterned, and the dev-auth flag and key are consistent-required together.
- `observability.mjs`: log fields carry only `{ts, service, method-label, route-template, status, duration_ms, random hex request_id}` — no tokens, subjects, or header values; route labels come from the template set (`unmatched` otherwise), so cardinality is bounded; the metrics gate requires loopback peer, exactly-one strictly-parsed loopback `Host`, and the absence of `origin`/`forwarded`/`via`/`x-forwarded-*`/`x-real-ip`, with `sec-fetch-site` ∈ {undefined, none} and GET only.
- Map growth: after fix 3, the limiter bucket map is bounded by `maxKeys` plus a per-window prune; the KYC/wallet directories are fixed synthetic fixtures.

## Observations (recorded, not defects in this slice)

- `isLoopbackPeer`/`isLoopbackHost` match dotted-quad patterns whose octets exceed 255 (e.g. `127.999.0.1` reads as loopback). The gate is belt-and-braces — a peer cannot spoof `remoteAddress`, and such a `Host` value is not routable — so it hardens the metrics gate rather than opening it; left for a later tightening wave.
- The limiter keys on the authenticated subject on a loopback-only service, so per-subject collapse into one bucket is by construction, not an aliasing defect.

## Test additions

- `packages/customer-api/tests/machinery-hardening.test.mjs` (7 cases): a non-finite verifier clock fails closed for valid, expired and over-TTL tokens; non-integer/non-positive `maxTtlSeconds`, `windowMs` and `maxKeys` are rejected at construction; a non-finite limiter clock denies with a well-formed retry hint; `generateUuidV7` returns a valid UUIDv7 for NaN, ±Infinity, fractional and negative readings; `validWalletsView` enforces the contract field patterns on fifteen drifted values; and a drifted `available` answers the `500` envelope with the offending value absent from the body.
- All new cases fail on main and pass on this branch.
