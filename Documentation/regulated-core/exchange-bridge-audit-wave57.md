# Customer API / Matching-Core Replay Bridge Audit — Wave 57 — Proposed

- Status: Proposed
- Scope: `packages/customer-api/src/exchange-orders.mjs` (the `exchangeOrderScenario` digest-derived market, `replayExchangeOrderScenario`, `projectExchangeOrders`/`projectExchangeTrades`/`projectExchangeMarkets`, the `validExchangeOrdersView`/`validTradesView`/`validMarketsView` guards and the three frozen directories), the serving arms in `packages/customer-api/src/app.mjs` (`getCustomerExchangeOrders`/`getCustomerTrades`/`getCustomerMarkets`), the boundary allowlist in `packages/customer-api/scripts/check-boundary.mjs`, and the cross-package seam into `packages/matching-core/src/{deterministic,engine,instruments}.mjs`. Everything is dev-only and synthetic — no production paths, no money movement, no approval or decision-register changes.
- Production effect: none

Hunt list applied: subject isolation (cross-request leaked state; counterparty liquidity attributed to a real `syn_cust_*` subject), digest hygiene (collisions between act types, truncation versus the id grammar, non-deterministic leaks), scenario robustness (hostile subjects, dead order ids, instrument drift, unprocessable self-trades, unfoldable journal events), projection correctness (VWAP, running remainder, status mapping, terminal stamps, book top, half-even spread), validator completeness (recompute versus shape-check), replay cost (bounded versus quadratic), the seam's minimality (allowlist drift, the leaf-vs-barrel pg trap), and the serving arms' failure path (capability check, fail-closed throw, double-send).

Method: candidate defects were reproduced as direct assertions against the real projection fold and guards — a journal can only ever come out of the real engine — and serving-arm claims as raw HTTP assertions against `startTestServer`. Falsified hypotheses were written down as pins.

## Defects found and fixed

1. **A quantity-less terminal echo erased the recorded remainder (medium).** The trails fold in `projectExchangeOrders` stored `terminalQuantity` on every `cancelled`/`rejected` journal event — including the quantity-less echoes a redundant cancel (`order_not_resting`) or a duplicate-id resubmission (`duplicate_order_id`) emits for a tracked order. After a real removal, the echo reset the remainder to null, so `base_amount` fell back to the order's placed total: a four-of-ten cancelled remainder was displayed as the full ten — the executed six units vanished from the view — and `updated_at` moved to the no-op's stamp. The fold still follows the last terminal-type stamp for `updated_at`, but it now stores a quantity only when the event actually carries one. Regression: `tests/exchange-bridge-audit.test.mjs` "a quantity-less terminal echo cannot erase the recorded remainder" (partial fill, cancel, then redundant cancel; and the duplicate-id-resubmit variant — both reported the placed total on the pre-fix fold) plus "a rejected order keeps the refused remainder through terminal echoes" (a same-owner refuse followed by a quantity-less cancel echo).
2. **Unknown scenario ops replayed as cancels (low).** `replayExchangeOrderScenario` mapped every non-`advance`/non-`submit` step onto `cancelOrder` — an `amend` step, or any mistyped or new op, silently cancelled the named order instead of surfacing scenario drift. The replay now throws `TypeError` on an unrecognised op. Regression: "replay fails closed on a step op it does not know" — on the pre-fix code the `amend` step cancels the order; after the fix it throws, and the generated op vocabulary is pinned to the declared three.
3. **`validExchangeOrdersView` admitted duplicated order ids (low).** The guard checked each row independently — two rows could claim one order record. An `order_id` is minted once per submission, so the list must carry unique ids; the guard now fails a repeat. Regression: "the orders validator rejects a view a projection could never emit" (a duplicated row is refused).
4. **`validTradesView` admitted duplicated trade ids (low).** Same class: a `trade_id` is minted once per (order, fill) pair, so the list must carry unique ids. Regression: "the trades validator rejects duplicated trade ids".
5. **`validOrder` admitted an impossible market-order status (low).** A market order never rests and is never cancelled — it fills (and the contract drops filled rows) or ends rejected — yet `open`/`cancelled`/`expired` market rows passed the guard. The guard now requires `order_type: "market"` to pair only with `status: "rejected"`. Regression: the same test — market rows crafted as open, cancelled or expired are refused. The canonical fixture in `tests/exchange-orders.test.mjs` encoded exactly this impossible state (`market` + `open`) and was repaired to `limit`.
6. **`validMarketsView` admitted a last trade after the snapshot close (low).** `last_trade.executed_at` was grammar-checked but never compared to `as_of` — a crafted view could place the final fill after the session's last second. The guard now requires `executed_at <= as_of` (the tail act executes inside the session, so equality stays admissible). Regression: "the markets validator rejects a last trade after the snapshot close" — an `executed_at` past `as_of` is refused while equality remains valid.

## Verified clean

- **Reads cannot cross subjects, and nothing survives a request.** Every `listFor` rebuilds the whole scenario and a fresh request-scoped `createMatchingEngine`; the directories keep no memo, cache, map or engine between calls (module level holds only frozen constants). Interleaved calls resolve byte-identical views, and different subjects' order/trade id sets are disjoint. Pinned: "cross-request state never leaks: concurrent and repeated reads agree".
- **Counterparty liquidity is never attributed to a subject.** The scenario vocabulary assigns `cust_*` owners to subject intents and `mm_*` owners to `cp-`-salted counterparty submissions — disjoint grammar, so the engine's same-owner self-trade policy can only fire between the subject's own rows, and `projectExchangeTrades` picks the subject leg by intent membership. Pinned: "scenario actors stay namespaced" (id grammar per role, a single subject owner per scenario, and cancel steps only ever target earlier submissions on the same instrument).
- **Every field is a pure function of the subject.** All ids and timings derive from `sha256(domain, subject, salt)` — `ord_`/`trd_` prefixes slice 24 hex chars of a 64-char digest, well inside the `^[a-z]{3}_[0-9a-f]{24}$` grammar; the salt vocabulary (`id:`, `cp-id:`, `cp-owner:`, `fill:`, `trade:`) is a fixed enumerated set, so a cross-type collision needs a sha256 prefix collision rather than a crafted subject; `Math.random`/`Date.now` appear nowhere in the module, and replaying one scenario twice yields identical journals. Pinned: the determinism suites plus "the projection fold tolerates a validation refuse before a later admit".
- **Generated scenarios are well-formed by construction and replay without error.** Every step is one of the declared ops; every cancel targets an id the same scenario submitted earlier on the same instrument; every pair is in `ORDER_PAIRS`; maker depth and taker sweeps are derived so quantities stay positive and inside the declared jitter band; `fee_bps` stays inside its small band, far under the engine's maximum. Pinned: "every act stays inside the declared instrument and quantity bounds".
- **The registry drift guard throws at module load.** The ORDER_PAIRS-versus-INSTRUMENTS check runs at import; a changed scale and a removed registry entry each kill a subprocess that imports the module — proven by replaying the check against a patched copy of the real files. Pinned: "the ORDER_PAIRS / INSTRUMENTS drift check throws at module load".
- **Projection correctness is pinned end to end.** Resting maps to open with a running remainder; cancelled maps to cancelled or expired by the intent's `expires` flag; a refuse maps to rejected with the refused remainder; filled rows drop from the orders list but emit trade rows; VWAP comes off the fill trail; `terminal_at`/`terminal_quantity` are now echo-proof; `last_trade`/`best_bid`/`best_ask` come from book state; `spread_bps` is half-even; empty-side levels stay null; `as_of` is the replay's last second. The older suites pin the emitted shapes; this wave adds the fold edges — "a cancelled-then-filled view never reports ghost executions" and the refuse-then-admit ordering pin.
- **Guards recompute every derived value they possibly can.** Amounts, fee, total, spread, scaled decimals, enums, key sets, ISO grammar and lifecycle coherence are all recomputed exactly — this wave closed the remaining coherence holes listed above. The shape-only-but-not-recomputable residue is enumerated in Observations.
- **Replay cost is bounded by a fixed act vocabulary.** Across 160 subjects the measured maxima stay small: under 41 steps, under 17 submissions, under 17 intents, under 513 journal events — nine acts (two opening fills, up to four ordinary acts, one tail, two ghosts) at a constant step count each, so the fold and the projections run linear in a small constant, never in the subject string. Pinned: "replay cost is bounded by the scenario's fixed act vocabulary". No per-subject structure retains anything — the no-unbounded-cache invariant from the earlier cross-directory wave holds.
- **The cross-package seam is minimal and pg-free.** `ALLOWED_CROSS_PACKAGE` names exactly the three leaves (`deterministic.mjs`, `engine.mjs`, `instruments.mjs`); any other `../` cross-package specifier — including the `index.mjs` barrel that would drag `pg` into the typecheck — fails the boundary check, and the transitive closure the leaves import (`book`, `decimal`, `events`, `journal-store`, `snapshot`) carries no `pg` specifier. Pinned: "the matching-core import seam stays minimal and dependency-free" (source scans of both the bridge's import list and the closure's).
- **The serving arms fail closed once, before headers.** All three reads require verified KYC plus the read capability; `listFor` runs, `validXView` gates, and a view that fails recompute (not merely shape) throws into the single 500 envelope — `send()` writes head and body once, and the throw always precedes headers, so double-send or a leaked body is structurally impossible. Pinned: "served reads fail closed on shape-valid content drift" (directories returning tampered `quote_amount`, `fee_amount` and post-close `last_trade` views all get the 500 envelope on their routes).

## Observations (recorded, not defects in this slice)

- On a terminal row, `updated_at` is the last terminal-type event about the order — a redundant echo can move the stamp without touching the remainder; that is the fold's documented semantics.
- The drift check is intentionally asymmetric: ORDER_PAIRS inside INSTRUMENTS is all the bridge consumes, and an extra registry entry can never reach a view.
- `expired` versus `cancelled` follows the intent flag, not the event cause — a crafted scenario can label a plain cancel expired; the engine cannot distinguish and the label stays scenario vocabulary.
- The served list is newest-first while the projection emits submission order — the same guard covers both directions because ordering is a directory-level convention (pinned in tests for trades earlier, now also for orders).
- An `amended` journal event is never folded — the scenario vocabulary cannot produce one and the fold treats it as a no-op.
- A `trade_id` is unique per view, but an `order_id` may repeat across trade rows (one order, several fills) — uniqueness is pinned per trade id only.
- Shape-only fields that can never be recomputed from the view alone: `status`/`order_type`/`liquidity`/`posting`/`execution`/`mode` truth, id digests against scenario salts, `as_of` and `created_at`/`updated_at` absolute values, `base_amount` for terminal orders, `order_count` on book levels — each is grammar- and coherence-checked instead, and the newest-first ordering is a served-view property pinned in tests, not a per-row rule.
- A rejected row born of an untracked validation refuse shows the placed quantity — there is no engine remainder to report; the fallback is intentional.
