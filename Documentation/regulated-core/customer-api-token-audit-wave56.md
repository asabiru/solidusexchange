# Customer API Synthetic Token Verifier Audit — Wave 56 — Proposed

- Status: Proposed
- Scope: `packages/customer-api/src/auth.mjs` (the `createSyntheticTokenVerifier` HMAC mint/verify path, `TOKEN_PATTERN`/`OPERATOR_TOKEN_PATTERN`, `sign()`, `parseBearerAuthorization`, the mint functions), `packages/customer-api/scripts/mint-dev-token.mjs` (argv → signature-covered material), `packages/customer-api/src/app.mjs` (principal validation and the `actorType` dispatch binding in `handleOperation`), `packages/customer-api/src/contract.mjs` (declared paths the audience classification is derived from), and `packages/customer-api/src/auth-sessions.mjs` (the session machinery the principal feeds). Everything is dev-only and synthetic — no production paths, no money movement, no approval or decision-register changes.
- Production effect: none

Hunt list applied: cross-family re-domaining (can a customer token become an operator token — is the audience bound inside the HMAC-covered payload or only in the prefix?), field rearrangement (prefix/segment surgery between parse and signing), the signature comparison (timing-safe compare on the full digest vs length-dependent shortcuts), expiry semantics (TTL window, clock trust, malformed/non-integer/huge fields, off-by-one, overflow, issued-in-future), subject smuggling (delimiters/whitespace/control/NUL/unicode, canonicalization between mint and verify), prefix-family confusion (`scdev1` vs `sodev1`, empty/extra segments, prefix inside subject), principal construction (`actorType` provenance, scope list provenance), `expiry10` units, the mint CLI (AUDIENCES exhaustiveness, argv injection), and the dispatch binding (`principal.actorType !== (operatorRoute ? "operator" : "customer")` — every path that could skip it).

Method: every suspected defect was reproduced as a unit-level assertion against the real verifier (crafted tokens minted with the test key, then asserted to reject) and, where the surface is the dispatcher, as a raw HTTP assertion against `startTestServer`. Falsified hypotheses were written down as pins.

## Defects found and fixed

1. **`mint-dev-token.mjs` parsed non-canonical `--ttl` forms (low).** The flag went through bare `Number()`, so argv forms that read differently than a decimal second count were silently taken: `--ttl 0x10` minted a 16-second token, `--ttl 1e3` a 1000-second one, and whitespace-padded (`" 60 "`), `+`-prefixed and leading-zero (`060`) forms parsed to values other than what they spell. The flag now requires canonical base-10 text (`/^[1-9][0-9]*$/u`) before conversion, matching how every other parsed field in the package behaves; the `1..3600` bound is unchanged. Regression: `tests/token-verifier-audit.test.mjs` "mint-dev-token rejects non-canonical ttl values" — `--ttl 0x10`, `1e3`, padded, plus-prefixed, zero-padded, fractional, zero, over-bound, negative, non-numeric and empty forms all exit 1 now; each minted or errored differently on main (proven: `0x10` minted a valid token on the pre-fix code, and the new test fails there).

## Verified clean

- **The audience is bound inside the HMAC-covered payload, and the verifier is sealed against re-domaining.** `sign()` HMACs `domain\nsubject\nexpiresText`, and `verify()` selects the domain solely from which family regex matched. Because the patterns are anchored end-to-end (`^scdev1\.(syn_cust_[a-z0-9]{8,32})\.([1-9][0-9]{9})\.([0-9a-f]{64})$` / the `sodev1`/`syn_oper_` twin), prefix, subject namespace, expiry grammar and signature are checked atomically — no byte can move a token across families: a prefix swap, a subject-namespace swap, both together, or the same fields MACed under the other family's domain all return null. Pinned.
- **Fields cannot be rearranged, emptied, duplicated or extended.** Reordered fields, empty segments, doubled dots, a trailing segment, a family prefix inside the subject slot, and case variants of the prefix all fail before the HMAC is even computed — and they would fail there anyway, because `subject`, `expiresText` and `signature` all come from the *same* regex match, so what the signature covers is byte-identical to what is dispatched. Pinned.
- **The comparison is the full 32-byte digest, timing-safe, and length-invariant.** `timingSafeEqual` runs on `Buffer.from(hex)` buffers that are always exactly 32 bytes (the grammar pins `[0-9a-f]{64}`), so malformed lengths can never reach a length-sensitive compare; truncation, extension, case folding and byte flips are all rejected. A token carrying a valid signature over *other valid material* still verifies — the check is authenticity, not byte-equality with one blessed token. Pinned.
- **The expiry grammar admits only canonical ten-digit epoch seconds.** The field units are seconds (not minutes): mint bounds it to `[1_000_000_000, 9_999_999_999]`, exactly the set `[1-9][0-9]{9}` describes, so negative, `+`-prefixed, fractional, exponential, leading-zero, 9-digit, 11-digit, whitespace-padded and empty forms can never reach `Number()` — they fail at the grammar, even with a correct signature under the right domain. `expiresAtSeconds * 1000` stays well inside the Date range, so `expiresAt` is always a valid ISO timestamp. Pinned.
- **The expiry window holds exactly at both boundaries.** `expiresAtSeconds <= nowSeconds` rejects an already-expired token at `now` (and every negative TTL); `expiresAtSeconds - nowSeconds > maxTtlSeconds` admits `now + 3600` and rejects `now + 3601`, for both families. Non-finite clocks already fail closed (pinned in `machinery-hardening.test.mjs`); a minted-in-the-future expiry beyond the TTL bound is rejected the same way. There is no "issued-in-future" claim to forge — tokens carry only an expiry. Pinned.
- **The subject grammar admits no smuggling surface.** `[a-z0-9]{8,32}` after the `syn_cust_`/`syn_oper_` literal excludes `.`, `/`, `\`, `?`, `#`, `%`, `_`, whitespace, tab, CR/LF, NUL, zero-width and non-ASCII bytes — each rejected even with a valid signature — so the subject segment can never carry a delimiter that would change what the HMAC covers versus what is dispatched. Mint validates the identical pattern, so mint output is always in the canonical form the verifier parses; a `syn_cust_` subject on the operator prefix (and vice versa) is rejected on both sides. Pinned.
- **Principal fields come only from the verified family.** `actorType` is derived solely from which regex matched — there is no audience claim in the token to lie about — and `scopes` are the server-side frozen constants `CUSTOMER_SCOPES`/`OPERATOR_SCOPES`, returned as frozen copies: mutating a principal's scope array throws and cannot poison the constants the capability policy trusts. `validPrincipal` in `app.mjs` re-validates subject/actorType/scope grammar/expiry independently before dispatch (a verifier violating the contract fails loudly as 500, never silently). Pinned.
- **`mint-dev-token.mjs` keeps argv out of the signature input.** `AUDIENCES` covers exactly the two minted families and is probed with `Object.hasOwn` (prototype keys like `__proto__`, `constructor`, `toString` are refused); `--subject` is re-validated by the mint function's per-family pattern, so cross-namespace subjects and shell metacharacters (`;`, `$()`, spaces) never reach `sign()`; argv can only name a pattern-valid subject plus an integer second count. Without `CUSTOMER_API_DEV_AUTH=synthetic` the script refuses to mint at all. Pinned (both audiences, namespace mixups, metacharacters, unknown audience, missing flag).
- **The dispatch binding has no skip path.** `principal.actorType !== (operatorRoute ? "operator" : "customer")` runs for every `authenticated: true` operation after `validPrincipal`. The classification is derived from the *declared* contract path (`path.startsWith("/api/v1/operator/")`), not the request target — so URL confusion cannot reclassify a surface: `/api/v1/operator` (no trailing slash), `/api/v1/operatorx`, trailing slash, `//`, `..`, `%2f`, `%00`, query, fragment, `;`-params, absolute-form, uppercase and literal-templated requests all answer 404 (or a 400 parse rejection) before any audience decision. The contract invariant is pinned: every `path.startsWith("/api/v1/operator/")` operation is a `getOperator*` and vice versa, and no `authenticated: false` operation may sit under the operator namespace. Pinned.
- **The audience check itself is reached, not bypassed, on the failure path.** An operator request must carry `X-Device-Id` (validated before auth — a 400 leak of a public rule, not a skip): a customer token with a valid device id reaches the binding and answers `401 AUTHENTICATION_REQUIRED`; an operator token on a customer path answers `401` symmetrically. Pinned.

## Observations (recorded, not defects in this slice)

- The signature check runs *before* the expiry check. This is the correct order — an unsigned expiry field is untrusted input and must not shortcut the cryptographic check — and it is why the "malformed expiry even with a valid signature" cases above are the meaningful ones.
- Synthetic bearer tokens are replayable by design until expiry: the token is `prefix.subject.expiry.signature` with no nonce or jti, and `maxTtlSeconds` (3600) caps the live window. Consistent with the dev-only contract; a replay cache would not change the threat model.
- `parseBearerAuthorization` matches the scheme case-insensitively (`bearer`/`BEARER`), which is what RFC 7235 allows; the token itself stays case-sensitive. Already pinned in `auth-config.test.mjs`.
- A 64-zero dev key satisfies `DEV_TOKEN_KEY_PATTERN` — the check asserts format, not entropy. Deliberate for a dev-only key loaded from the environment; recorded.
- `verify` trusts `clock()` for `nowSeconds` and `validPrincipal` re-checks expiry against the app clock — an injected clock divergence between the two fails closed or loudly (500), never silently permissive.
- `mintSynthetic*Token` signs `expiresAtSeconds` as a number while `verify` re-signs the captured decimal text; the grammar's canonical form (`[1-9][0-9]{9}`, no leading zeros) makes the two byte-identical, which the round-trip pins now lock down.
