# Backoffice BFF Server Route-Table Audit — Wave 70 — Proposed

- Status: Proposed
- Scope: `backoffice/src/server/server.ts` — the single `createBackofficeServer` dispatch monolith carrying the `/bff/*` route table (the metrics scrape pin, healthz, the OIDC login/device/status/callback arms, dev-session and logout, the session/signing-key/operator reads, the dashboard and customer collections, the five fetch-site-guarded audit-appending families, the step-up challenge/verify/preview POSTs) plus the seams it delegates to: `customer-api-client.ts` upstream binding, `data/client.ts` `verifyEnvelope`, `session.ts`/session stores, `device.ts` admitted-device gate, `oidc.ts` pending-flow store, `observability.ts` route-label machinery. Everything is dev-only and synthetic — no production paths, no money movement, no real customer data.
- Production effect: none

Hunt list applied: dispatch order and method-mismatch uniformity, trailing-slash/case/double-slash and percent-decode normalization, `?query` rejection parity and duplicate-parameter semantics against the upstream strict allowlists, session/device gate ordering and enforce-mode information shape, cookie scoping (`Path=`) and first-wins parsing, OIDC pending-flow bounds and generic `auth_failed` mapping, `/bff/api/*` upstream path construction and response caps, degrade-mode coherence, `verifyEnvelope` resource binding per route, and the absence of an SPA fallback behind `/bff/*` typos.

## Defects found and fixed

1. **`decodeURIComponent` threw uncaught `URIError` on two member arms, answering 500 where every sibling member read answers its uniform 404.** `/bff/api/operator/subjects/:id` and `/bff/api/operator/queue/:kind/:id` (both segments) decoded their captures outside any guard — `GET /bff/api/operator/subjects/%` and `GET /bff/api/operator/queue/kyc/%zz` (authed) fell into the outer catch-all → 500 `request_failed`, while `/bff/api/checks/%`, `/bff/api/support/%`, `/bff/api/withdrawals/%`, `/bff/api/subjects/%/timeline` and `/bff/api/reports/%` answered their own `*_not_found`. A 500 on malformed client input is both outside the shared error taxonomy and a dispatch fingerprint — the two upstream-backed arms were distinguishable from the local ones. Repro-failed on main (`500` actual); fixed by wrapping each decode in the same try/catch → `operator_subject_not_found` / `operator_queue_item_not_found` the sibling arms already pin.
2. **`?query` rejection was not uniform across GET surfaces — the wave-68 class, ported.** Of ~31 GET views only `/bff/api/operator/audit` rejected undeclared keys (`operator_audit_query_invalid`); every sibling — the collections, the member reads, `/bff/healthz`, `/bff/auth/device`, `/bff/auth/status`, `/bff/api/signing-key`, `/bff/api/signing-keys`, `/bff/api/session` — answered 200 with `?audit=w70` silently dropped, and even the five declared-input routes tolerated foreign keys (`/bff/api/checks?status=created&junk=1` → 200; `/bff/api/operator/queue?kind=kyc&debug=1` → 200). A silently ignored parameter reads as applied input — the same failure mode the member reads and the upstream contract reject outright. Repro-failed on main (`200` actuals). The fix mirrors wave-68: a `queryInputGetRoutes` map names the only five query-declaring routes and their exact key sets (`{kind}`, `{cursor}`, `{status}` for checks/support/withdrawals); one pin inside the shared session/capability funnel — every guarded route requires `authorized(request, response, url, capability)` — answers 400 `invalid_request` on any undeclared key, GET-scoped so the POST arms keep their posture; the six pre-session public GETs reject inline (login rejects only after its unconfigured→404 hidden-route check); the OIDC callback keeps tolerating foreign keys (observations). Ordering preserved: unauthenticated still resolves the session first (401 before 400).
3. **`/bff/api/operator/queue` was weaker than the upstream strict allowlist it proxies.** The arm read `url.searchParams.get("kind")` — first-wins — so `?kind=kyc&kind=aml` served the kyc queue while upstream `operatorQueueKind` treats a repeated `kind` as invalid input → 400; undeclared keys were never inspected. Repro-failed on main (`?kind=kyc&kind=aml` → `200` actual). The fix mirrors the audit feed's own contract: `getAll("kind").length > 1` → 400 `operator_queue_query_invalid`, out-of-enum keeps `operator_queue_kind_invalid`, undeclared keys hit `invalid_request` via the uniform pin — nothing rejected ever reaches upstream (pinned by stub-call counting).
4. **Method mismatch was non-uniform: five families answered 405 + `Allow: GET` while ~24 sibling GET views answered 404 — a fingerprint for which views append audit evidence.** POST/PUT/DELETE/OPTIONS/HEAD on `/bff/api/checks`, `/bff/api/support`, `/bff/api/withdrawals`, `/bff/api/subjects/:ref/timeline`, `/bff/api/reports` (list+member+export) got `method_not_allowed`; the same verbs on `/bff/api/customers`, `/bff/api/dashboard`, `/bff/api/kyc`, `/bff/api/session`, every operator read and every literal route hit the floor → 404 `not_found`. The divergence leaks which routes the audit pipeline writes to. Repro-failed on main (`404` actuals on the unguarded family). The fix lifts the family's contract to one dispatch-order gate after the metrics arm — `literalGetViews` plus `memberGetViewArms` name every registered GET view; a non-GET on any of them answers 405 + `Allow: GET` — and removes the five now-redundant in-block checks. POST-only paths deliberately stay outside the map (GET on `dev-session`/`logout`/the step-up `APV-*` arms keeps 404 — observations); the unconfigured OIDC arms and the disabled metrics scrape keep their own ordering.

## Verified clean (with negative pins)

- **Dispatch order has no shadowing.** Every exact-path arm runs before the regex member arms (`/bff/api/operator/subjects` collection before `/subjects/:id`; `/queue` before `/queue/:kind/:id`; `/checks` before `/checks/:id`); no longer prefix is swallowed by a shorter arm, and the step-up `APV-*` POSTs run only inside their exact method arms.
- **POST-only paths hide uniformly.** GET on `/bff/auth/dev-session`, `/bff/auth/logout` and the three step-up `APV-*` arms answers 404 `not_found` — the same shape as a never-registered path — pinned alongside HEAD/OPTIONS/PUT/DELETE on them.
- **Path normalization cannot smuggle a route.** Literal comparisons against `url.pathname` keep `/bff/api/customers/`, `/bff/api//customers`, `/BFF/...`, `/bff/API/...` at 404; WHATWG `URL` resolves dot-segments before dispatch so `/bff/api/../customers` normalizes to `/bff/customers` → 404; percent-encoded spellings (`%63ustomers`) never equal the literal route keys, and after the fix malformed member encodings take the uniform `*_not_found` with no 500 path remaining.
- **The query pin resolves the session first.** Unauthenticated `?audit=w70` still answers 401 `operator_session_required` before any 400 — the pin sits after session+capability inside the shared gate, so no auth oracle opens in front of it.
- **Device/session gate ordering leaks nothing.** The session resolves through the single `currentSession` before any route arm; enforce-mode device denial routes through `oidcAuthFailed` → generic `/?error=auth_failed` redirect with the device cookie preserved — the same 302 shape a replayed or missing transaction gets, never a route-specific reason. `deviceBinding` has only `off`/`enforce` — no half-open report mode exists to leak.
- **Cookie scoping holds the wave-65/66 port.** `parseCookies` is first-wins, blocks `__proto__`, stores malformed encodings as empty; the session and device cookies scope `Path=/bff`, the OIDC transaction cookie `Path=/bff/auth` with `SameSite=Lax` — a forged `Path=/` cookie of the same name cannot shadow the scoped value because browsers order more-specific paths first and the parser keeps the first occurrence it receives.
- **OIDC pending flow is bounded and generic.** `maxPendingLoginsPerInitiator` 2 + `maxPendingLogins` 256 + `oidcTransactionTtlSeconds` 600; the callback requires exactly one `code` and one `state` (`getAll` multiplicity checks); every failure path — missing tx, nonce mismatch, bad code, bad state, device denial — funnels to `oidcAuthFailed`'s `/?error=auth_failed` with an empty tx cookie that preserves the device cookie (the #321 posture); `state`/`nonce`/`verifier` are `createOpaqueValue` outputs, never reflected from the request.
- **Upstream URL construction cannot smuggle params.** Member ids re-encode per segment via `encodeURIComponent`, contract-pattern pre-flight guards (`customerSubjectPattern`, `queueItemIdPatterns`, `auditCursorPattern`) answer locally for non-contract ids, every `get()` runs `AbortSignal.timeout` + `redirect: "error"` + `readBoundedJson` under `maxCustomerApiResponseBytes` (16_384) — `?`/`#`/`%` in a member id reaches the upstream as inert escapes only.
- **Degrade is fail-closed.** Upstream `not-configured`/`unavailable`/non-ok maps to the `*_unavailable` 503 family or the documented unconfigured synthetic view behind `customerApi.configured === false` — no fabricated live-looking rows on upstream failure; `operatorCapabilityVocabulary` pins the six upstream capability ids the session echo compares against.
- **Envelope binding is per route and per member.** Every served read and the step-up POSTs go through the `signer` envelope helper with a route-specific `resource` — collections (`dashboard`, `customers`, `operator-subjects`, `operator-audit:first`), members (`check:${id}`, `report:${id}`, `operator-subject:${id}`, `operator-queue-item:${kind}:${id}`) — and the app-side `verifyEnvelope` demands `envelope.resource === expectedResource` exactly, so an envelope minted for route A can never satisfy route B or a different member; keyset lookups refetch on key miss and staleness, `issuedAt` must be canonical ISO-8601 inside the skew window, retired keys die at `retiredAt`, and an `unsigned` error body surfaces as `ApiError`, never as a verified payload.
- **No SPA fallback exists to catch `/bff/*` typos.** The BFF is API-only — `index.ts` is a 26-line bootstrap and the Vite dev server serves the app separately — so every unmatched `/bff/*` spelling hits the floor → 404 `not_found`; the metrics scrape keeps its raw `request.url` pin (`!== "/bff/metrics"` → 404, then GET-only 405 inside its own arm) ahead of every shared gate.

## Observations (recorded, not defects in this slice)

- `pendingLogins.take(state)` consumes the pending transaction before `admittedDevice` runs — a device-denied callback cannot be replayed; single-use consumption is the recorded posture (denial still preserves the device cookie).
- The OIDC callback is exempt from the key allowlist by design: it declares `error`/`code`/`state` and tolerates foreign keys because conformant providers append their own (`iss`, `session_state`) — a strict allowlist would break those flows. Login, device and status take the strict posture instead.
- POST arms ignore `?query` uniformly — the pin is GET-scoped, matching the pre-existing unauthenticated write paths (`POST /bff/auth/logout?x` was always 404-hidden anyway).
- The per-initiator pending-login cap keys `flow:${state}` for cookieless initiations, so each anonymous attempt self-roots a new initiator key — the global 256 bound is the real backstop for anonymous floods, same shape as the miniapp's recorded posture.
- GET on POST-only paths stays 404 — deliberately outside the new 405 map so writes and probes on them remain indistinguishable from absent surface; the metrics scrape keeps its own ordering (disabled → 404 before any method check) ahead of the shared gate.
