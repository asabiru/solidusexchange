# Provider Simulators Internals Audit — Wave 38 — Proposed

- Status: Proposed
- Scope: `packages/provider-simulators/src/` internals on main — `kyc.mjs`, `kyt.mjs`, `bank.mjs`, `quotes.mjs`, `checks.mjs` domain handlers plus the shared machinery in `simulator-core.mjs` (idempotency registry, delivery queue, request snapshot, scenario resolution), `callback-inbox.mjs` (verified-callback state machine), `signing.mjs` (callback signer and verifier), `canonical-json.mjs`, `decimal.mjs`, `deterministic.mjs`, `errors.mjs` and `interfaces.mjs`. Cross-domain external behavior was covered by the conformance suite; this wave hunted defects inside the package itself. The package is a pure deterministic library — there is no `server.mjs` or HTTP dispatch, and webhook targets are not configurable (deliveries are pull-based via `drainCallbacks`), so callback-URL injection and server-dispatch items had no applicable surface.
- Production effect: none

Hunt list applied: malformed-body crashes, signature verification bypasses (algorithm confusion, unsigned messages, timing), webhook replay handling, idempotency-key collisions across different payloads, state leakage between subjects, unbounded growth in stores and indexes, prototype-key confusion on scenario names or request fields, decimal/exact-math violations in quote and bank math, error bodies leaking internals, callback URL injection, header validation gaps.

## Defects found and fixed

1. `validateChecksCallback` in `checks.mjs` let any `outstanding_amount` through on closed statuses as long as it differed from the check amount. The documented invariant — outstanding equals the amount while open (`created`, `awaiting_recipient_kyc`) and is zero otherwise — was enforced only as `open !== (outstanding === amount)`, so a forged-but-authentic callback claiming `claimed`/`cancelled`/`expired`/`awaiting_confirmation` while carrying `outstanding_amount: "5.000000"` (or the full amount) passed verification and would poison the consumer's reconciliation view. The validator now requires `outstanding === 0` for every closed status, and the same check rejects `sender_ref === recipient_ref` in callbacks, matching the create-time rule.
2. `createPaymentIntent` in `bank.mjs` let the `partial_payment` scenario run on an amount of one minor unit (`0.01` RUB). The draw produces `paid = 1` = expected, so the simulator emitted a `partial_payment` callback whose own validator cannot admit it (`paid < expected` is required) while `getPaymentStatus` reported `received_total` equal to the expected amount under a `partial` status — a self-inconsistent provider response. The intent now fails closed with `invalid_request` when the resolved scenario is `partial_payment` and the expected amount is below two minor units.
3. `claimCheck` in `checks.mjs` compared the stored claim digest with `!==` on hex strings. The claim reference is the bearer handle to a check, so the comparison must not early-exit on the first differing byte; it now uses `timingSafeEqual` over the two digests, matching the HMAC comparison in `signing.mjs`.
4. The event intake of `createCallbackInbox` in `callback-inbox.mjs` trusted `receivedAt` and `payload.sequence`. A non-finite or non-integer `receivedAt` (NaN, Infinity, a string) bypassed the deadline check (`receivedAt > deadline` is false for NaN), so timed-out subjects could keep applying events; a `sequence` that is not a positive integer was coerced with `Number()` — `NaN` sailed past every comparison and was applied, `"1"` was silently treated as valid, and `1.5` or `1001` could be parked forever. The intake now asserts `receivedAt` is epoch seconds, requires `isPositiveSequence` on the raw payload value, and holds malformed events for review (`invalid_transition`) instead of applying them.
5. The same intake computed `sha256Hex(payload)` before validating anything else, so a payload member that cannot be canonically serialized (NaN, a fractional number, a throwing `toString`) surfaced as a thrown `JsonError` — the library equivalent of a malformed-body 500 on the consumer path. Serialization now happens inside a guarded conversion that counts the event for review as `invalid_transition`, and non-object payloads are refused with `TypeError`.
6. `DeliveryQueue.schedule`/`drain` in `simulator-core.mjs` and `CallbackInbox.expire` did not validate their time arguments. `drain(NaN)` drained nothing but still filtered `pending` with a `NaN` comparison — silently dropping every queued delivery; `expire(NaN)` silently no-opped. All three entry points now assert epoch seconds, consistent with the verifier's clock checks.
7. `openSubject` admitted non-string subject ids (a numeric id stored under a `Map` number key can never match a string payload reference). It now requires a non-empty string.

## Verified clean

- Signature verification in `signing.mjs`: the algorithm is bound to the key id at keyring lookup (no `alg` member is taken from the message), `v1=` envelope lengths are pinned per scheme before verify, HMAC comparison uses `timingSafeEqual`, Ed25519 uses `crypto.verify`, timestamp staleness and future-skew bounds are enforced, the nonce store is bounded (10 000) and fails closed when full, and the canonical body must re-serialize byte-identically — an envelope whose body was altered in whitespace or key order is rejected before payload validation.
- Header normalization: duplicate header names (including case-folded duplicates), non-string or overlong values and invalid header names are all rejected before signature checks; only the four scheme headers are read.
- Idempotency in `simulator-core.mjs`: the digest covers the whole snapshotted request (`sha256` of the canonical form), so the same key with a different payload is an `idempotency_conflict`; responses are `structuredClone`d on both store and replay, and `snapshotRequest` refuses non-plain objects, accessors, symbols and unknown members — no cross-key collision or prototype-confusion path exists.
- Scenario resolution: `validateScenarioPlan` builds a frozen `Object.create(null)` map and `resolveScenario` checks membership by `includes` on the known list, so `__proto__`, `constructor` or inherited names cannot resolve.
- Decimal/exact math: all amounts are parsed and carried as `bigint` minor units with fixed per-asset scale (`decimal.mjs` refuses floating-point input, exponent forms and scale overflow); quote math rounds buy legs up and sell legs down exactly as documented, the budget solver's binary search lands on the first non-fitting base amount, and `validateSignedQuote` re-derives every field.
- Error bodies: `ProviderError` messages are fixed call-site strings or validated field names — no internal state (digests, keys, stored references) is echoed.
- Webhook replay: re-delivery is intentionally modeled (`duplicate_callback` scenario), and the inbox's `event_id` dedupe plus conflict detection covers it on the consumer side; the verifier's nonce store makes re-delivery of an envelope bearing a valid signature detectable.

## Observations (recorded, not defects in this slice)

- In-memory stores are per-resource and grow linearly with actual resources created: `IdempotencyRegistry.entries`, `DeliveryQueue.pending`, inbox `subjects`/`events`, and the per-domain `timelines`/`intents`/`checks`/`quotes` maps have no internal eviction — bounding them would change idempotency and replay semantics, which callers rely on. Dev-only fixture scale keeps this theoretical.
- `kyc.mjs` `reviewTimeoutSeconds` and `kyt.mjs` `screeningTimeoutSeconds` admit any value above their floors; a huge value surfaces as a `RangeError` from `toIsoSeconds` inside the idempotent run rather than a clean `invalid_request`. Cosmetic inconsistency — the operation is still refused before any state is recorded.
- Getter (`getApplicantStatus`, `getPaymentStatus`, `getCheckStatus`, `getQuote`) lookups key on caller-supplied ids and answer `not_found` for misses; provider references are unguessable `SIM_ID` handles by construction, so there is no cross-subject enumeration surface beyond what the adapter contract already delegates to the caller.
- `assertProviderAdapter` in `interfaces.mjs` walks `Object.getOwnPropertyNames` through the prototype chain; symbol-keyed members cannot collide with the forbidden camelCase operation names, and the forbidden-operation lookahead intentionally permits noun forms such as `paymentStatus`.

## Test additions

- `packages/provider-simulators/tests/internals-audit.test.mjs` (12 cases): closed-status callbacks with nonzero outstanding amounts rejected at the validator and end to end via a forged envelope carrying a valid signature; self-check callbacks rejected; `partial_payment` at `0.01` RUB refused before any intent or callback exists while `0.02` stays self-consistent; malformed `receivedAt`, `sequence`, payload content and non-object payloads held for review or refused; malformed `expire`/`drain`/`schedule` times rejected without dropping pending work.
- All new cases fail on main and pass on this branch (the `0.02` partial-payment control passes on both).
