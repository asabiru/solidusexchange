# Backoffice BFF Core Audit — Wave 34 — Proposed

- Status: Proposed
- Scope: `backoffice/src/server/` core machinery on main — `server.ts` routing/session handling, `oidc.ts` + `session.ts` + `step-up.ts` + `device.ts` auth flow, `signing.ts` + the client-side envelope verification in `backoffice/src/data/client.ts`, `audit-store.ts` / `postgres-audit-store.ts` / `audit-bootstrap.ts`, `security-headers.ts`, `request-body.ts`, `controls.ts`, `observability.ts`, `config.ts`, `access.ts`, `reports.ts`, `provider-evidence.ts`, `vite.config.ts`
- Production effect: none

Hunt list applied: session fixation or expiry gaps, step-up credential reuse or downgrade, signature-verification bypass (alg confusion, missing key-id pinning, unsigned data where envelopes must be signed), audit-chain breaks (append without the required headHash, snapshots without re-verification), timing or parse edge cases, fail-open guards (a missing header answering allowed instead of denied), unbounded memory growth, prototype pollution, error bodies leaking internals, CORS or origin bypasses, cookie flag issues.

## Defects found and fixed

1. `parseCookies` in `server.ts` ran `decodeURIComponent` on every cookie pair without a guard. A single `Cookie: x=%` header made every request that touched `parseCookies` throw `URIError` — answered as 500 on routes that should deny (401) or proceed anonymously. The pair is now skipped on decode failure, matching browser leniency; a malformed session cookie therefore reads as absent and fails closed.
2. `new URL(request.url, \`http://${request.headers.host}\`)` in `server.ts` parsed the client-supplied `Host` header unguarded. A syntactically valid header such as `Host: a b` or `Host: [bad` crashed route resolution with `Invalid URL` — 500 on every route including `/bff/healthz`. The parse is now caught and answered `400 invalid_request`.
3. `isLoopback` in `server.ts` stripped an IPv6 prefix by `split(":")[0]`, so a configured bare `BACKOFFICE_BFF_HOST=::1` resolved to the empty string and never matched the loopback set — `/bff/auth/dev-session` permanently 404'd on an IPv6-loopback BFF even with `BACKOFFICE_ALLOW_DEV_LOGIN=true`. `isLoopback` now recognizes the bare `::1` form.
4. `SyntheticStepUpService` kept its per-binding lookup indexes keyed by bindingId, which changes on every audit-head movement. No index entry for an expired challenge or required grant was ever removed unless the same binding was operated on again — unbounded memory growth on a long-running BFF. `begin`, `verify` and `consume` now prune index entries whose records no longer resolve in the expiring stores, and a new `indexSizes()` diagnostic exposes the bound to tests.
5. `buildApprovalPreview` in `controls.ts` threw `Audit chain is empty` when the store held no events, surfacing as a 500 on the preview route. The anchor now falls back to `{ sequence: 0, hash: auditGenesisHash }`, consistent with the genesis head the snapshot status already reports for an empty chain.

## Verified clean

- Session lifecycle: re-login revokes the prior session and the session that started the login flow; device binding is re-checked on every authenticated read and evicts other sessions sharing the device id; `SameSite=Strict` + `Path=/bff` + `HttpOnly` on the session cookie, `Secure` when every allowed origin is https (config forbids mixed http/https, so the flag rule is consistent); the OIDC transaction cookie is `SameSite=Lax`, path-pinned to `/bff/auth/callback`, 300 s, and the pending-login entry is single-use (`take`).
- OIDC verification: alg pinned RS256, `kid` required and uniquely matched in JWKS, `crit`/`jku`/`jwk`/`x5u`/`x5c`/`b64` header members rejected, RSA ≥2048-bit, `use=sig`, `key_ops` exactly `[verify]`, claims `iss`/`aud`/`azp`/`exp`/`iat`/`nbf`/`nonce` validated, duplicate JSON members rejected, role resolved via own-property map with ambiguous membership rejected.
- Step-up flow: the binding covers session + subject + the required approval id + command digest + audit head hash; challenges are single-use with bounded attempts; each pending grant is single-use (`take`) and supersedes an earlier pending grant on the same binding, TTL-bounded; `binding_mismatch` rejects before the code check so probing does not burn attempts.
- Response signing: Ed25519 keyset rotation keeps a bounded retired set; envelope verification client-side pins `keyId`/`keyVersion`/`signatureVersion`, validates keyset shape (unique ids, exactly one active, `activeKeyId` consistent), ISO `issuedAt` with 5-minute skew, `retiredAt` bound, canonical-JSON payload digest, WebCrypto verify before unwrap; unsigned routes (`healthz`, `signing-keys`, `auth/*`) are public by design.
- Audit store: memory and Postgres stores re-verify the whole chain on every snapshot and append, enforce `expectedHeadHash`, dedup `eventId`, hash-check every row on read; the Postgres path is SERIALIZABLE plus advisory lock, strips all `ssl*` url params and pins `rejectUnauthorized`; `#storeError` hides internals behind `audit_store_unavailable` → 503.
- Request guards: the body parser caps 4 KiB, requires `application/json` (optional `charset=utf-8`), a flat string-valued object, no duplicate keys, an exact per-route key allowlist; every mutating route requires an exact `Origin` allowlist match; audit-appending GET views require `sec-fetch-site` ∈ {same-origin, none}; `/bff/metrics` requires loopback peer + loopback `Host` + no `origin`/`forwarded`/`via`/`x-forwarded-*`/`x-real-ip`/`proxy-*` headers, raw request-target check, GET only (405 otherwise); wrong methods on every other `/bff/*` route answer 404.
- Error surface: `RequestBodyError` → 400/415 `invalid_request`, `AuditStoreError` → 503, `StepUpRejectedError` → 409, `OidcRejectedError` → 403; anything else → generic `request_failed` 500 with no internals.
- Security headers: frozen api/document/dev-document header sets applied uniformly including the `guardRawResponses` clientError (400/408/431) and checkExpectation (417) paths; the Vite dev server applies the same sets via `prependListener` and denies non-loopback binds.
- Config: refuses `NODE_ENV=production` and non-dev dry-runs; loopback-only host set; `allowedOrigins` exact-matched, no http+https mixing, http only on loopback; OIDC requires all six fields, redirect URI pinned to `/bff/auth/callback` on an allowed origin, https except loopback, no credentials/hash in URIs; all TTLs integer-bounded; device digests validated, deduped, and requiring `enforce` mode.

## Observations (recorded, not defects in this slice)

- `retentionDays` on the memory audit store is a status label only — events are never purged; the synthetic store stays bounded by demo traffic, and durable retention is a Postgres-side decision.
- The step-up indexes are pruned on service calls rather than by a timer — consistent with the lazy-expiry `ExpiringStore` pattern used everywhere else.
- A session-cookie pair that fails percent-decoding is dropped individually; other pairs in the same header still parse — deliberate so a malformed marketing cookie cannot break auth.

## Test additions

- `backoffice/src/server/bff-core.test.ts` (6 cases): a malformed cookie pair is ignored (status 200 / dashboard 401 / a valid session cookie still reads), a malformed `Host` is answered `400 invalid_request`, dev login is admitted with `BACKOFFICE_BFF_HOST=::1`, expired step-up challenge and pending-grant bindings are pruned to the live bound, and the required approval preview anchors at the genesis hash on an empty audit chain. All six fail on main and pass on this branch.
