# Matching Core Order-Book Semantics Audit — Wave 69 — Proposed

- Status: Proposed
- Scope: `packages/matching-core/` matching logic on main — `engine.mjs` (order intake, the `matchTaker` sweep, `emitFill`, `cancelOrder`, `amendOrder`, `beginOperation`/`stamp`/`emit`/`finish`), `book.mjs` (price levels, FIFO queues, `bestHead`/`shiftBest`/`remove`), `decimal.mjs` (canonical decimal gates), `events.mjs` (order/event shape gates, `SELF_TRADE_POLICY`), `instruments.mjs` (per-pair scales), plus the emission/journal contract that wave-59's replay pipeline consumes. Snapshot validation was audited in wave-59 (#301) and the replay-mirror bridge in #295; this wave is the first dedicated pass over the matching logic itself. The package is a pure data-only library: fills carry `posting: "none"` and nothing posts to a ledger, so no money-movement surface exists inside it.
- Production effect: none

Hunt list applied: same-price FIFO and same-instant tie-breaks, multi-level sweeps in price order, equal-price different-quantity sequencing, tail re-queue after priority-losing amends; self-trade at the level head, behind an honest fill, beyond the aggressor's limit, across instruments, amend-induced, ownerless orders, owner case-sensitivity, and the rest a reject leaves behind; the amend priority matrix (price change, quantity increase, quantity decrease, normalized no-op, at-or-below-filled totals, terminal states, crossed amends matching in the same call); zero and quantum-edge quantities, dust remainders, fill-sum conservation, market residuals into full and empty books, IOC/FOK spellings; decimal drift at 0.1 granularity, scale boundaries, canonical-spelling level merge, the 18-significant-digit wall, non-canonical spellings; cancels of filled/cancelled/unknown/wrong-instrument orders, partial-fill cancels, cancel-versus-aggressor call order, terminal-id consumption; event envelope integrity, emission ordering, contiguous `seq`, per-operation timestamps, frozen journal views, store-visible commit order, re-entrant entry through the journal-store seam, and batch splicing by a hostile store.

## Defects found and fixed

1. **`book.remove` half-applied a removal it reported as failed (`book.mjs`).** The removal deleted the resting index entry first and looked up the order's price level second; when the level lookup missed or the queue no longer held the order it returned `false` with the index entry already gone — the order stayed in the level queue, still matchable and still fillable, while `restingOrder` reported nothing. No public path reaches that divergence today (the amend path is the only caller that moves `price_units` and it removes first), but any future caller mutating a resting order's price before removal would strand the queue entry. `remove` is now atomic: it locates the level and confirms queue membership before mutating anything, returning `false` with the book untouched, and `true` only when the order is fully out of index, queue and level.
2. **`emit` let payload fields shadow the event envelope (`engine.mjs`).** Event construction spread `fields` after `stamp()`, so a payload key named `seq`, `at`, `type` or `posting` would overwrite the engine-assigned envelope — `seq`/`at` ordering and the `posting: "none"` marker could be forged by whatever built the field object. Every call site today passes fixed literal keys, so nothing reaches this; `emit` now strips the four reserved keys from the payload copy before spreading, so the envelope can never depend on caller discipline.
3. **A journal store could re-enter the engine mid-operation and splice into the emitted batch (`engine.mjs`).** `finish` ran `journalStore.append(events)` while the operation was still open and the batch array still mutable: a backend calling `submitOrder`/`cancelOrder`/`amendOrder` inside `append` re-entered `beginOperation` and interleaved state and `seq` counters, and a backend pushing into `events` spliced un-emitted records into the in-memory journal (`journal.push(...events)` ran after `append`). `beginOperation` now refuses while an operation is open — `operationAt` stays set from the first clock read until `finish` clears it, so re-entrant entry throws `reentrant matching operation` before any state is touched; `finish` seals the batch with `Object.freeze` before the store sees it, so `append` receives a read-only view it cannot splice; and `operationAt` clears in a `finally`, so a synchronous `append` throw still closes the operation instead of leaving every later call reporting re-entrancy.
4. **The README still claimed the pre-wave-59 owner gap (`README.md`).** The "honest gap" paragraph said order-acceptance events carry no `owner`, so a replayed engine loses owner tags and self-trade protection has nothing to compare. That was true before #301 and false since: order-acceptance events now carry `owner`, the fold validates it with `isOwner` and threads it into tracked state, and a replayed engine still enforces self-trade (re-pinned in the new suite). The paragraph now describes the shipped behavior.

## Verified clean

- **Price-time priority.** Two rests at one price fill strictly in submission order; rests stamped at the same instant still queue in acceptance order — the `seq` counter is the tie-break; an aggressor sweeping three levels drains best price outward at maker prices; equal-price rests of different quantity sequence in arrival order regardless of size; a re-priced order joins the tail of its new level behind earlier rests.
- **Self-trade protection.** The policy is `reject` (no skip or cancel-own variant exists): an own rest at the book head rejects the aggressor's remainder only — earlier same-operation fills at other levels stand, the taker goes terminal `rejected`, and the own rest stays untouched and fillable by other owners. An own rest beyond the aggressor's limit never trips the check; the comparison is per-instrument (the same owner on two pairs does not interact, while the check still bites inside one pair); an amend re-priced into the owner's own opposite rest rejects `self_trade` inside the amend call; ownerless orders never self-trade; owner matching is exact and case-sensitive (`Desk-A` differs from `desk-a`).
- **Amend semantics.** Cancel-replace under a stable `order_id`: a price change or a quantity increase loses time priority and re-queues at the tail; a quantity decrease at an unchanged price keeps its slot; `quantity` is the new total — at or below the already-filled part rejects `quantity_below_filled`; an amend normalizing to no change rejects `no_change` (submitted `90` versus stored `90.00000000`); amends on filled, cancelled, rejected or unknown ids reject `order_not_resting`, and market orders never rest so they are never amendable; a priority-losing amend whose new price crosses the book matches in the same call — `amended` then fill pairs at maker prices — and never rests at a crossed price.
- **Partial fills, dust and market residuals.** Zero-quantity submissions reject `non_positive_quantity` and consume no order id; the smallest scale unit rests and fills exactly; fill quantities plus the remainder always equal the submitted total (bigint minor units, no drift); a market order draining the book rejects its remainder `insufficient_liquidity` and never rests; a market order into an empty book rejects whole; only `limit` and `market` types exist — IOC/FOK spellings reject `invalid_type`, and a market order carrying a price rejects `invalid_order`.
- **Decimal exactness.** All arithmetic is bigint minor units: 0.1-granularity partials sum exactly; values one unit past an instrument's scale reject (`0.0000001` at quantity scale 6, `0.000000001` at price scale 8) while the scale unit itself works; equivalent spellings (`90` versus `90.00000000`) canonicalize into one level in arrival order; the 18-significant-digit wall rejects past-limit prices and quantities; non-canonical spellings (`090`, `.5`) reject rather than rounding or coercing.
- **Cancel lifecycle.** Cancelling filled, cancelled or unknown ids rejects `order_not_resting`; a cancel addressed to the wrong instrument does not touch the order; a partially filled cancel removes only the remainder (the `cancelled` event echoes it) and the order goes terminal with zero remaining; a cancel frees its level for the next aggressor; cancel-versus-aggressor resolves strictly in call order — the engine is single-threaded and single-flight, so no interleaved semantics exists; terminal ids (filled, cancelled, rejected) stay consumed forever, while validation-rejected ids never got consumed.
- **Event and journal emission.** A crossing submission emits its order-acceptance event first, then the maker-side fill, then the taker-side fill, then the terminal event (`resting`/`filled`/`rejected`); rejection-only operations emit a single `rejected` and still journal it; `seq` is contiguous `1..N` across submissions, fills, rejects and cancels; every event of one operation shares one clock read; `journal()` returns a fresh frozen array of frozen events, so caller mutation throws and cannot reach the engine; a journal store's `append` observes post-operation book state against the pre-commit journal — state commits before the batch is durable; replayed engines keep owner tags and still enforce self-trade.
- **Book internals.** `remove` is atomic post-fix (pinned white-box on a divergent index/level state in both directions); `remove` clears index, queue and the emptied level; `bestHead`/`shiftBest` keep index and queue in step on every path the engine takes.

## Observations (recorded, not defects in this slice)

- A synchronous `journalStore.append` throw still propagates with live book/tracked state mutated but the batch unrecorded — the trade-off wave-59 recorded: the journal always lands on operation boundaries, never truncated mid-batch, while live state can run ahead of the recorded prefix. The new guards narrow the surface (no re-entrant operation inside `append`, no splicing the sealed batch); the throw path itself is unchanged.
- A clock whose `now()` calls back into the engine sits outside the new guard by construction — `beginOperation` reads the clock before the operation opens, so a re-entrant submission taken inside `now()` proceeds through every later invariant check and can at most reorder two independent operations' emission order, deterministically. The documented seam is `journalStore`; `createSimulatedClock` is a pure counter.
- `finish` classifies an `append` result with `instanceof Promise`: a non-Promise thenable from a non-compliant store is treated as synchronous — a contract violation on the store side (`createPostgresJournalStore` returns a real `Promise`; `createMemoryJournalStore` appends inline).
- Depth aggregation past roughly a million maximum-quantity rests at one price level could overflow the 18-integer-digit formatter on `bookSnapshot` — theoretical at this package's scale; recorded for completeness.
- `amended` echoes previous and new price/quantity; `cancelled` echoes the removed remainder; neither carries `owner` — terminal events do not need it for the fold, which restores owner tags from order-acceptance events.
- `bookSnapshot`/`orderStatus` throw `TypeError` on an unknown instrument rather than emitting a rejected event — an API-misuse contract distinct from the in-band `unknown_instrument` rejection on order paths.
- Self-trade keys on owner equality alone — same-owner orders on opposite sides at non-crossing prices coexist freely, and there is no per-account or net-position policy beyond it. There is likewise no minimum-quantity or lot-size policy beyond the instrument scale: one-unit dust rests and matches freely.
- No FOK exists: a market order is the immediate-or-cancel semantic — it fills what it can and rejects the remainder, never all-or-nothing.
