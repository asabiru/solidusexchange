# GitHub Checkers Audit — Wave 75 — Proposed

- Status: Proposed
- Scope: `.github/scripts/check-verification-integrity.mjs`, `check-workflow-policy.mjs`, `check-regulated-core-status.mjs`, `check-dev-stack.mjs` and their co-located `*.test.mjs` files — the meta-gates that pin the audit baseline, the GitHub Actions policy, the regulated-core document-status conventions and the local dev stack. The question was the wave-#327 question applied to the gates themselves: can a change bypass these checkers while staying green? Every finding was reproduced against the pre-fix checker first (mutate the target surface, observe the checker still passes), fixed in the same change, and pinned by a regression in the co-located tests. Everything is dev-only and synthetic.
- Production effect: none

## Defects found and fixed

1. **`baseline.scripts` pinned only the listed names; unlisted scripts slipped.** Adding `"postinstall": "curl ...|sh"` (or any extra script) to a pinned `package.json` stayed green — the validator only checked that pinned names matched. Fixed: the actual script-name set must equal the pinned set exactly; an extra name errors `script "x" is not pinned in the baseline`.
2. **`baseline.runSteps` was subset matching.** Any `run:` step could be added to a pinned workflow — including a step that mutates test files before `npm test` runs — and the checker stayed green (a co-located test even codified the gap). Fixed: the actual run-command multiset must equal the pinned multiset exactly; extra steps error `run step is not pinned in the baseline`. An empty `runSteps` entry now means "this workflow may contain no run steps" (deploy.yml) rather than "nothing asserted".
3. **`baseline.testFiles` covered only listed files.** An added test file (`*.test.*` or anything under a `tests/` dir) ran no risk of being noticed — proven in the wild: `backoffice/src/data/demo-oracles.test.ts` and `miniapp/src/server/synthetic-oracles.test.ts` landed in a merged PR and were never repinned. Fixed: every file matching the existing `TEST_PATH` predicate must appear in `testFiles` or the new `unpinnedTestFiles` waiver list; stale or non-surface waiver entries fail too. The two drifted test files are now pinned with real counts; the two `tests/helpers.mjs` files and the e2e compose fixture are waived.
4. **New manifests and workflows escaped pinning entirely.** A brand-new `package.json` or `.github/workflows/*.yml` file was not a member of any baseline section, so its scripts and run steps were unconstrained. Fixed: repository completeness requires every `package.json` on disk to appear in `scripts` and every top-level workflow file in `runSteps`.
5. **`uses:` references and container/service images were unpinned.** Swapping `actions/checkout@<sha>` for a different 40-hex SHA, or pointing a service at another digest-pinned image, stayed green in both checkers. Fixed: new baseline sections `uses` and `containerImages` pin the exact reference multisets per workflow (all 12 workflows, deploy included).
6. **Trigger path filters were unpinned and children unchecked.** `paths:` under `pull_request:`/`push:` is load-bearing per-package CI, but its values were unpinned (CI coverage could silently shrink), `types:` was unrestricted (e.g. `types: [opened]` skips pushes to the PR), and `paths: []` was legal. Fixed: new `triggerPaths` baseline section pins the exact filter lists; the workflow-policy checker now rejects any `pull_request`/`push` child other than `branches`/`paths` and requires non-empty block lists.
7. **`runs-on:` was unrestricted.** `runs-on: [self-hosted, linux]` or `${{ matrix.os }}` stayed green, moving jobs to uncontrolled runners. Fixed: validation-workflow jobs must declare exactly `runs-on: ubuntu-latest` (block and flow styles checked; pure-alias jobs inherit from the checked anchor; reusable-`uses:` jobs exempt; deploy.yml exempt as the approved manual workflow).
8. **Job-level `secrets:` was unchecked on validation workflows.** `secrets: inherit` on a job (the channel that forwards every repo secret to a reusable workflow) stayed green. Fixed: any `secrets` key on a validation-workflow job — block or flow style — errors.
9. **Baseline shape was unvalidated.** `testFiles: {}`, `scripts: {}`, `requiredPhrases: {}`, a top-level `[]`, or non-numeric `minLines` all silently passed (loops just iterated nothing). Fixed: `validateBaselineShape` (verification-integrity) and `validateStatusBaseline` (regulated-core-status) require all sections present, non-empty and typed; a missing or malformed baseline file now fails with a named error instead of an uncaught exception or a silent pass.
10. **Tracked files under skipped directories escaped the integrity walk.** `dist/`, `coverage/`, `node_modules/`, `.test-dist/`, `.server-dist/` are skipped because they are build output — but a committed file there (e.g. `git add -f` a `test.only`) was invisible. Fixed: `git ls-files` enumerates tracked paths; any tracked file under a skipped directory errors.
11. **Unpinned regulated-core documents could omit status entirely.** A new `.md` with no `- Status:` line stayed green (only documents *with* status lines were checked against the Proposed/Draft vocabulary). Fixed: an unpinned document must declare `- Status: Proposed` or `- Status: Draft`.
12. **`check-dev-stack` silently ignored unknown files and never checked e2e wiring.** A `.py` file under `infra/local` matched no file class and was skipped; a symlink was dropped by the walk without a word; a committed `.env` (skipped by design for local use) was invisible even if force-added; and the `packages/e2e-dev` package enumerated its `lint`/`test` file lists by name, so a new `tests/*.test.mjs` could exist forever without running. Fixed: unmatched files error `unexpected file under the dev stack root`; non-regular entries error; a `.env` that is git-tracked errors; `checkE2ePackage` requires `node --check`/`node --test` scripts to cover every `tests/*.mjs`/`tests/*.test.mjs` and references no missing file.

## Verified clean (with negative pins)

- **Missing pinned files already failed**: a deleted pinned package manifest, workflow or test file errored before this change; the same holds for pinned regulated-core documents.
- **Trigger-event totality already held**: `pull_request_target`, `workflow_dispatch`, `schedule` and any other event key on a validation workflow were already rejected; the manual `deploy.yml` is restricted to `workflow_dispatch` only.
- **Permissions and action hygiene already held**: root `permissions` must be exactly `contents: read`, job-level permissions are banned, `uses:` requires a 40-hex SHA (or digest-pinned `docker://`, or a local reusable workflow), `actions/checkout` requires `persist-credentials: false`, YAML tags, explicit `?` keys, quoted/escaped key smuggling and `${{ }}` in run text were already rejected.
- **`if:`/`continue-on-error` gagging already held**: conditional and error-swallowing jobs on validation workflows were already rejected.
- **Container/service digests already required**: `container:`/`services:` images had to carry `@sha256:` digests (this wave adds pinning of *which* digest).
- **Regulated-core hygiene already held**: confusable-folded snapshot diffs for pinned docs, Unicode/markup/HTML-comment tricks, non-`.md` entries and non-regular entries were all rejected; recursive enumeration covers `adr/` subdirectories.
- **Source-text rules already held**: focused/skipped tests, `process.exit`, selective `--test-*` flags, unlisted `process` member access and dynamic-code patterns were already rejected repo-wide.
- **Dev-stack semantics already held**: non-root users, no privileged services, loopback-only ports, digest-pinned images, no anchors/merge keys, NODE_ENV bans and the committed-secret patterns were all enforced — this wave adds the file-class completeness and wiring they assumed.
- **Loud failure already held for the walk itself**: non-regular entries anywhere else in the repo already errored; JSON parse failures already crashed (loud) — now they are also cleanly named.

## Observations (recorded, not defects in this slice)

- **Content-level test pinning is count-based by design.** `minLines`/`minCases` catch gutting that removes lines or cases but not a same-size rewrite of a test body; full hashing was rejected as too heavy for the repin workflow. The new completeness rule plus `uses`/`triggerPaths` pinning narrows the practical blast radius (a weakened helper file under `tests/` still needs a waiver entry to exist, and weakening commands injected into workflows now need a repin).
- **`deployment/*.sh`, `app/` PHP, `SQL/install.sql`, `assets/` scripts have no checker watching their semantics.** Deployment scripts sit outside `TEST_PATH`, so even the shell strict-mode rules do not apply; the PHP and SQL surfaces are outside every checker's grammar. Recorded as the largest remaining cross-checker gap — a follow-up policy decision (extend `TEST_PATH`-style shell rules to `deployment/`, or a dedicated deploy checker) rather than a silent fix.
- **`.github/workflows/` subdirectories are unenumerated.** `workflowFiles()` reads the top level only; GitHub would not run a nested workflow either, so the gap is cosmetic — but a nested `.yml` is examined by no checker at all.
- **`paths:` filters remain human-judgement territory.** They are now pinned, but whether a repinned filter still covers the right surface is a review question the checker cannot answer.
- **`concurrency`, `environment`, `timeout-minutes` and `strategy.matrix` are ungoverned** on validation workflows; none are used today, and none carry secrets or runner control once `runs-on` and `secrets` are pinned. Left unwatched deliberately; flag for a future wave if one appears.
- **Checkers now depend on a git work tree** (`git ls-files`) for the tracked-under-skipped-dirs and tracked-`.env` checks; both run inside the repository in CI and locally, and a non-repo root (unit-test temp fixtures) degrades to "untracked" rather than failing.

## Test additions

- `check-verification-integrity.test.mjs`: flipped "accepts added workflow run steps" to rejection; added rejects for unlisted script names, malformed/empty baselines, unpinned or swapped `uses`/`containerImages` references, `triggerPaths` drift, and unpinned test-surface/manifest/workflow completeness plus stale waivers.
- `check-workflow-policy.test.mjs`: kept the `paths:` acceptance (load-bearing design), added rejection of `types:`/`branches-ignore`/empty `paths:` trigger filters, self-hosted and matrix-expression runners, and job-level `secrets:`; flipped the `${{ matrix.os }}` runs-on fixture to rejection.
- `check-regulated-core-status.test.mjs`: added rejection of status-less unpinned documents (including a `- Production effect: none`-only doc) and malformed/empty status baselines; the negated-wording fixture now carries the required `- Status: Proposed`.
- `check-dev-stack.test.mjs`: added rejection of unexpected file types and symlinks under the stack root, and `checkE2ePackage` coverage for unwired `tests/*.test.mjs` and stale script references.
