# Backoffice customer-api client audit — wave 76

- Status: Proposed

Wave 76 line-audits `backoffice/src/server/customer-api-client.ts` (~1.8k lines — the BFF's upstream client to the dev customer-api serving the operator surfaces: admin, subjects roster, subject-360, the three queue collections and member reads, and the oversight audit feed). #303 audited the adapter layer and #349 the miniapp client; this file's post-#303 surfaces (audit feed, queue items, subject-360 blocks) had never been audited end-to-end. The operator channel serves plain JSON contract views (`mode: "test"`) — the envelopes the BFF signs for its own downstreams live in a different layer (wave-60/#332) — so the audit oracle is the upstream `valid*View` guard set in `packages/customer-api/src/operator.mjs`: every contract pin upstream enforces when it mints a view must fail closed client-side when a served body drifts. Each defect below was reproduced as a failing test before the fix landed in the same change.

## Defects found and fixed

1. **Queue-item member read never bound the answered id to the requested id.** `parseOperatorQueueItemDetailView` validated `value.kind === kind` and the item's own shape, but `item.queue_id` only had to match the kind's ref pattern — a response naming a different (well-formed) queue item than the path asked for passed. The upstream member guard recomputes the detail for the requested id verbatim, so a misbound row is impossible upstream and now fails closed client-side: the parser takes the requested `itemId` and requires `item.queue_id === itemId` for all three kinds (the #303 member-binding class, now closed on the newest member read).
2. **Queue collections trusted any item order.** `parseOperatorQueueView` checked each item's shape and the summary tally but never the page order. Upstream sorts kyc and aml items by `sla_due_at` ascending with `queue_id` breaking equal instants, and tickets by `opened_at` ascending with the same id tie-break; a misordered page now fails closed.
3. **AML item detail trusted an unordered flag list and instants past the horizon.** The detail parser bounded the flag count and id grammar but not the list order or `raised_at`. Upstream pins flags oldest-first (`raised_at` ascending, `flag_id` tie-break) and rejects any raise past the pinned snapshot instant; both now fail closed.
4. **KYC dossier attempts trusted instants past the horizon.** `parseSubjectKyc` enforced the review-window, resubmission and newest-first rules but left the attempt submission/decision instants unbounded at the roster's pinned as-of instant. The upstream dossier guard rejects both past the snapshot; the client now does the same (covering the dossier inside the subject-360 view and the kyc queue-item detail alike).
5. **Ticket detail trusted a `last_message_at` past the horizon.** The tickets member read validated the field as ISO but not the upstream `<= QUEUE_SNAPSHOT_MS` bound; it now fails closed.
6. **Recent-activity items trusted instants past the horizon.** `parseSubjectRecentActivity` bounded instants at registration and (subject-side only) `last_active_at`, but never at the roster's snapshot. The upstream activity guard rejects any `occurred_at > QUEUE_SNAPSHOT_MS` — the client now does for every row, subject- or operator-side.
7. **Audit feed trusted a drifted `as_of` and cross-kind target refs.** The parser passed any well-formed ISO `as_of` through as the entry horizon, and validated `target_id` against one union pattern — so `queue.viewed` entries naming an `osn_*` session ref, or `subject.viewed` naming a `flg_*` flag ref, passed. Upstream pins `as_of === AUDIT_AS_OF_ISO` exactly and each `target_kind` its own ref grammar (session→`osn_*`, queue_item→`qky_*|qml_*|qtick_*`, subject→`syn_cust_*`, flag→`flg_*`). The client now pins the same as-of instant and binds the grammar per target kind; the pinned as_of also bounds `entry.at` via the existing horizon check.
8. **`age_ms` trusted as a free non-negative integer.** Upstream derives kyc items' `age_ms` as `QUEUE_SNAPSHOT_MS − submitted_at` and tickets' as `QUEUE_SNAPSHOT_MS − opened_at` — arithmetic on the wire fields the client already validates. The collection and member parsers now require the exact derived value for both kinds.

## Verified clean

- **Request lifecycle.** One fetch per read with a single `AbortSignal.timeout(2000)` total bound — no retries at all, so no 4xx retry, no retry-storm and no per-attempt drift; `redirect: "error"`, bounded 16 KiB body requiring `application/json` (case-insensitive, content-length lie or mid-stream growth both fail), fatal UTF-8 decode, JSON.parse inside the same catch arm.
- **Local guards before the wire.** Every method validates `X-Device-Id` grammar locally (unavailable without a call); `operatorQueue` answers non-enum kinds locally, `operatorQueueItem` answers out-of-pattern ids — including well-formed ids of another kind — and `operatorAudit` non-`auc_*` cursors as the uniform `not-found` without an upstream call.
- **Member-read binding elsewhere.** `operatorSubject` binds `subject_id === requested subject` and `operatorAdmin` binds `subject === minted principal`; the queue-item gap (defect 1) was the only unbound member read.
- **Error mapping.** Member reads map upstream 404 → `not-found` (real miss, not drift) and every other non-200 → `unavailable`; the deliberate absence of a `denied` arm is documented in the client — upstream hands these reads to every operator token, so a refusal is contract drift.
- **Capability negotiation.** The capability echo validates against the operator vocabulary as a dictionary (dedupe + bounded length), not a pattern; the audit read presents the fixed `syn_oper_0000000000000002` principal that deterministically draws the auditor role holding `operator.audit.read` — the feed does not vary by reader and per-user authZ stays in the BFF route's own gate.
- **Queue-kind coherence.** `?kind=` is built as a single encoded param from the enum — a duplicate or unknown kind can never be emitted; both parsers reject `queue.kind !== kind`/`view.kind !== kind` so an item answered under the wrong kind fails closed.
- **Collection invariants.** Exact key sets at every level, unique queue_ids/audit_ids/flag ids/evidence refs/device refs, summary tallied to the row set, evidence refs bounded 1..8 with per-ref grammar, non-empty page bounds (subjects 1..64, audit 1..32, activity 1..8, kyc history 1..4, queue ≤64, flags ≤8).
- **Audit feed pairing.** `action`→`target_kind` pairing is exact per the feed vocabulary; entry order is newest-first with the descending-id tie-break; `next_cursor` requires the `auc_*` grammar or null.
- **Envelope surface.** Not this client's layer: the upstream serves plain contract views and the BFF's outbound envelope minting is audited in wave-60/#332. No verifier can apply wrongly — there is none here.
- **Decimal/ISO canon.** Every money field is the canonical scaled decimal (`^(0|[1-9][0-9]*)\.[0-9]{scale}$`, zero only where the closed-account rule allows) and every timestamp reserializes to itself (`new Date(Date.parse(v)).toISOString() === v`), killing normalizing parse artifacts.

## Observations

- **`age_ms` for aml items stays a non-negative-integer check only**: upstream derives it from the alert's `raisedMs`, which is not a wire field — the arithmetic cannot be re-derived client-side (defect 8 covers the two kinds where it can). The flag list's `raised_at` bound still covers the horizon for the detail read.
- **`next_cursor` minting is not client-verifiable**: the upstream guard requires the minted token for the next offset; the client checks grammar and lets a well-formed-but-never-minted token round-trip to the upstream 404 → `not-found` mapping. The page↔cursor binding upstream enforces is not re-derivable in the client.
- **429 collapses to `unavailable`**: the union exposes no `rate_limited` status, matching the documented two-status degrade design (refusals are drift, not real denials); a distinct operator-facing rate-limit signal would be a contract change, noted not fixed.
- **The snapshot pin is redeclared, not imported**: `QUEUE_SNAPSHOT_MS`/`AUDIT_AS_OF_ISO` are module-private upstream constants, so the client redeclares the derivation (`Date.parse("2026-09-01T00:00:00.000Z") + 150 * 86_400_000`) next to the audit constants with a comment naming the upstream symbol.

## Test additions

New cases in `backoffice/src/server/customer-api-client.test.ts`, each written to fail on the unfixed parser: subject-detail drift list gains four snapshot-horizon variants (subject-side and operator-side activity instants past the pin, kyc submission/decision instants past the pin while inside the account window); a new `operatorQueue` case table covers per-kind misorder, equal-instant id tie-breaks and kyc/tickets `age_ms` arithmetic; a new `operatorQueueItem` case table covers member queue_id binding per kind, flag order/tie-break/snapshot bound, ticket `last_message_at` bound and `age_ms` arithmetic; the `operatorAudit` drift list gains the `as_of` pin drift plus one cross-kind target-ref variant per target kind.
