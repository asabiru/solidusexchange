# Miniapp Market-Depth Adapter Audit — Wave 63 — Proposed

- Status: Proposed
- Scope: `miniapp/src/server/customer-api-client.ts` (`marketDepth` + `parseMarketDepthView` and the sibling `parseMarketsView`/`parseTradesView`/`parseExchangeOrdersView` adapters), `miniapp/src/server/markets.ts` (`contractMarketDepthView`), `miniapp/src/server/server.ts` (`/bff/markets/:instrument` depth route and `/bff/operations/:id` order-detail route, incl. `knownGet` `/:param` matching), `miniapp/src/app/` (`MarketsSheet.tsx`, `markets-depth.ts`, `api.ts`).
- Production effect: none

Architecture mapping (recorded for reviewers): the market-depth read is the newest upstream member read (#308) — a `{instrument}` path-param route served percent-encoded in one segment, bound through the BFF to `/api/v1/customer/markets/:instrument`. The adapter parses the wire view against `validMarketDepthView` semantics from `packages/customer-api/src/exchange-orders.mjs` (16-level cap, best-first ordering, uncrossed book, `depth_levels` consistency, `last_trade <= as_of`), stamps scales from the pair catalog, and the route converts client outcomes into the member-read error surface (404 `not_found` / 503 `markets_unavailable`, never a fabricated ladder).

Hunt list applied (#303/#305 classes): fail-closed validation completeness (every invariant the served validator enforces must hold adapter-side), cross-record echo/member-binding on `{instrument}` routes, scale stamping from `contractQuotePair` vs injected pairs, depth cap vs `depth_levels` consistency, `last_trade`/`as_of` ordering edges, malformed percent-encoding / double-decode of `%2F` in one segment, degrade arms never fabricating a ladder, error-object identity across all upstream statuses, and the `knownGet` `/:param` template widening.

## Defects found and fixed

1. **`isIsoTimestamp` skipped the upstream canonicalizer (`customer-api-client.ts`).** The shared helper checked the pattern and a finite `Date.parse` — but `Date.parse` *normalizes* out-of-range components: `2026-02-31` rolls into March, `2026-04-31` into May, `T24:00` into the next day. Upstream requires the stamp to reserialize exactly (`new Date(Date.parse(v)).toISOString() === v`); the adapter admitted drift the served validator rejects. Because the helper is shared, every timestamp field across every parser was reachable (`as_of`, `last_trade.executed_at`, `executed_at`, `created_at`, `updated_at`, `submitted_at`, `deadline`, `expires_at`, operation timeline `at`s): a drifted view parsed, then rendered the *normalized* instant — wire string and displayed time silently differ. The helper now mirrors the reserialize pin.
2. **`parseTradesView` allowed duplicated `trade_id`s (`customer-api-client.ts`).** Upstream `validTradesView` pins `new Set(ids).size === length` — a repeat is two rows claiming one execution record. The adapter validated each row but never uniqueness. Now pinned; two fills of one `order_id` with distinct `trade_id`s still serve (multi-fill is legal).
3. **`parseExchangeOrdersView` allowed duplicated `order_id`s (`customer-api-client.ts`).** Same class: upstream `validExchangeOrdersView` pins id uniqueness (minted once per submission). Now pinned.
4. **`parseMarketsView` dropped two collection invariants (`customer-api-client.ts`).** (a) The canonical instrument sequence: upstream requires `markets.length === ORDER_PAIRS.length` and `instrument === ORDER_PAIRS[i].pair` — every declared pair reports precisely once, in order. The adapter admitted any dedup'd subset or reorder, so a partial/drifted collection would have rendered as the instrument list in MarketsSheet. (b) `last_trade.executed_at <= as_of`: upstream `validMarket` rejects a fill post-dating the snapshot — the depth parser carried the bound but the collection parser did not. Both pinned; the dedup set is subsumed by the exact sequence and removed.
5. **`/bff/markets/:instrument` tolerated undeclared query strings (`server.ts`).** The route ignored `url.search`: `GET /bff/markets/USDT%2FRUB?trace=1` served the full ladder. Upstream `queryOperation` rejects a query on this operation, and every newer member read (`/bff/address-screening/:id`, `/bff/support/requests/:id`, `/bff/checks/:id`) pins `url.search === ""` → `400 invalid_request`. Pinned identically, before segment decoding.
6. **`/bff/operations/:id` had the same missing pin (`server.ts`).** The order-detail member read (an "adapter around" the depth surface per the wave scope) tolerated `?query` while its sibling member reads reject it. Pinned identically.

## Verified clean (with negative pins)

- **Member binding on `{instrument}`**: `marketDepth` rejects any view whose `instrument` differs from the requested pair — pinned by the existing drifted-body matrix (`instrument: "TON/USDT"`, `"BTC/EUR"` → `unavailable`). The served `pairDef` resolves through `contractQuotePair`, and base/quote assets must match it, so an ok for another book is unreachable.
- **Scale stamping cannot be bypassed**: the wire depth view carries no scale fields — `base_scale`/`quote_scale`/`price_scale` are stamped from `contractQuotePairs` keyed by the *bound* instrument. An injected pair either fails catalog resolution (`unavailable`) or fails base/quote asset equality; the catalog order and scales mirror upstream `ORDER_PAIRS` (USDT/RUB 6/2, TON/RUB 9/2, TON/USDT 9/6, `PRICE_SCALE` 8).
- **Depth cap and `depth_levels` consistency mirror exactly**: sides over 16 reject; `depth_levels` must be a safe int ≥ the served side maximum and equal it whenever no side hit the cap — the served validator's exact rule.
- **Ladder invariants mirror**: non-null levels (nullability is the collection read's empty-side convention only), exact level keys, scaled-positive decimals, `order_count` safe int ≥ 1, no duplicate prices, bids strictly descending / asks strictly ascending, best bid < best ask when both sides rest.
- **`last_trade`/`as_of` edge bound**: `executed_at > as_of` rejects on both the member read and (now) the collection; the `===` boundary stays inside the replayed session — pinned by the boundary control in the new suite.
- **Decode-once discipline on the route**: a single `decodeURIComponent` over a single segment — `%ZZ` undecodable → 404, a literal `/` splits extra segments → 404, and `%252F` double-encoding decodes once to a literal `%2F` → pattern fails → 404 (new pin in the malformed matrix). The client's own `marketInstrumentPathPattern` pre-check additionally reports a malformed name as `not-found` without spending an upstream call.
- **Degrade arms never fabricate a ladder**: a KYC-gated session or the standalone unconfigured BFF answers 404 `not_found` *without consulting upstream* (no local depth fixture exists at all); an upstream `denied`/`not-found` degrades to the same 404; every other outcome answers 503 `markets_unavailable`.
- **Error-object identity is deterministic**: 403 → `denied` → route 404; 404 → `not-found` → route 404; 401/429/500/other → `unavailable` → route 503 — and error bodies are never parsed for codes. Pinned by the existing status matrix.
- **`knownGet` `/:param` widening is inert**: the `/bff/markets/:instrument` template admits any `/bff/markets/` suffix at the pre-session gate, but it only shifts unknown paths from a pre-session 404 to a 401 — session is still required and the handler re-validates the segment shape, KYC gate and configuration before any upstream call. No precheck bypass; pinned by the "requires a session" 401.
- **Parser throws degrade, never escape**: a pattern-valid decimal wider than the adapter's 30-digit `toUnits` conversion throws inside the parser and is caught by each read method's outer catch → `unavailable` (route 503), preserving error identity. New negative pin covers a giant ask price, a giant bid quantity, and a giant trade quantity.
- **`contractMarketDepthView` (`markets.ts`)** is a pure adapter over the already-validated view — `Date.parse` runs on canonical stamps only; the app renders through fail-closed `format.epochMs` and `MarketsSheet` maps 404 → `markets.notFound`, anything else → `common.serverUnreachable`.
- **`depthTruncated` mirrors the cap semantics**: `depthLevels > max(bids, asks)` is exactly the served contract's "a side hit the 16-level cap" signal — the truncation note can never fire on a full book and always fires when levels were cut.

## Observations (recorded, not defects in this slice)

- **Collection-level query tolerance is a convention split, not this surface's defect**: `/bff/trades`, `/bff/exchange-orders`, `/bff/markets`, `/bff/operations` tolerate `?query` like several older siblings, while the notifications/sessions/support/checks/address-screening families pin `url.search === ""`. Member reads are now uniformly pinned; whether the collection family should follow is a repo-wide convention decision for a future wave.
- **The uniqueness/set class remains open on collections outside this wave's named scope**: upstream pins set-completeness for wallets (exactly the `WALLET_ASSETS` set), deposit-addresses and address-screenings (exact `(asset, network)` target sets) and bounded-feed shape for operations/activity (length bounds, unique ids, unique kinds, strictly decreasing `created_at`). `parseWalletsView`/`parseDepositAddressesView`/`parseAddressScreeningsView`/`parseOperationsView`/`parseActivityView` do not mirror those yet — recommend a follow-up wave sweeping the remaining collection parsers with the same catalog.
- **`depth_levels` cannot be re-derived adapter-side**: it reports the deeper side's true book depth before the served cap — only the ≥-served/===-served-when-uncapped pin is checkable, which is exactly what both validators enforce.
- **Subject binding lives upstream**: the replayed scenario derives from the token subject inside customer-api; the wire view carries no subject field to echo — identical to the served contract.
- **The 30-digit unit bound makes the adapter *stricter* than the wire validator** for absurd magnitudes (upstream `parseUnits` is unbounded). Stricter is the fail-closed direction and unreachable for anything the simulator can serve; it degrades to `unavailable` rather than throwing, which the new pin covers.
