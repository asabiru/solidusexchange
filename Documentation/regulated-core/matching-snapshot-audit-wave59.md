# Matching Core Snapshot/Restore + Replay Audit — Wave 59 — Proposed

- Status: Proposed
- Scope: `packages/matching-core/` restore-validation pipeline on main — `snapshot.mjs` (`parseEngineSnapshot`/`hydrateEngineState`, bookSnapshot v2), `replay.mjs` (`replayMatchingEngine` fold, `replayMatchingJournalStore`), `engine.mjs` emission/commit path, `journal-store.mjs` memory backend, `postgres-journal-store.mjs` and `migrations/0001_matching_journal.sql` (`append_matching_journal`, `validate_journal_sequence`). The package is a pure data-only library: fills carry `posting: "none"` and nothing posts to a ledger, so no money-movement surface exists inside it.
- Production effect: none

Hunt list applied: hostile snapshots (non-8dp decimals, crossed books, duplicate order ids, resting orders on unknown instruments, negative/zero/NaN quantities, missing/extra fields, ordering violations, symbol-keyed fields, hostile nesting), byte-identical restore through every path (live engine, journal replay, durable journal rows; key ordering, decimal normalization, `tracked` insertion order, timestamps), adversarial fold streams (out-of-order, duplicated, gapped seqs, unknown orders, fills before order acceptance, amends on non-resting orders, cancels of filled orders, market-order resting echoes, events inside fill pairs), `seq`/`fill` boundary behaviour (empty journal, `seq` 0, `seq`/`fill` at the safe-integer bound, `validate_journal_sequence` parity between memory and postgres backends), namespace isolation and advisory-lock atomicity under concurrent appends, the write-behind `tail` queue and first-failure `latch`, snapshot format versioning (v1/v3/unknown, unbounded sizes, non-object payloads), and clock invariants (`last_at`/`at` versus `seq` ordering, `beginOperation` sampling).

## Defects found and fixed

1. **Snapshots restored crossed books a live engine can never produce (`snapshot.mjs`).** `parseEngineSnapshot` verified each resting order's shape, decimals, unknown instruments, duplicates and `resting`-list order — but never compared sides. A snapshot resting a bid at `95.00000000` next to an ask at `90.00000000` on one instrument passed validation and hydrated into `bookSnapshot` as crossed liquidity, even though every live submission sweeps matches before anything rests. Restore now computes best bid/ask per instrument over the validated resting set and refuses any book where `bid >= ask` (`invalid engine snapshot: resting orders form a crossed book`), in either direction including the equal-price boundary, on any instrument.
2. **Journal replay lost `owner`, breaking byte-identical restore and self-trade protection (`engine.mjs`, `replay.mjs`).** Order-acceptance events never carried `owner`, so the fold restored tracked entries with `owner: undefined`. Two real divergences followed: a replayed engine's `snapshot()` serialized `owner: null` where the live engine still held `"desk-a"` — breaking the replay-is-restore contract the whole pipeline is built on — and, worse, self-trade protection silently switched off for pre-replay orders: a taker from the same desk crossing a live resting order its own stream had recorded was refused `self_trade` before replay and filled cleanly after. Order-acceptance events now carry `owner` when the order has one (the emission already validated it at submission), the fold validates it with the same `isOwner` predicate and threads it into tracked state and snapshot output. Streams recorded before this change — order-acceptance events without the field — still fold; their owners restore as `undefined` exactly as documented before, while new streams preserve owners end to end.
3. **Snapshot counters told contradictory stories (`snapshot.mjs`).** An engine with no emitted events always has `last_at: null`, `next_seq: 1` and `next_fill: 1`; any emitted event stamps `last_at` and consumes `seq`. The validator passed the impossible mixes — a stamp with no events (`next_seq: 1`, `last_at: t`), events with no stamp (`last_at: null`, `next_seq: 5`), and consumed fills with no events (`next_seq: 1`, `next_fill: 5`). Restore now enforces the correlation: `last_at` is null exactly when `next_seq` is 1, and `next_seq` of 1 requires `next_fill` of 1.
4. **Emission counters could run past what restore admits back (`engine.mjs`).** A restored engine whose `next_seq` sat at the safe-integer bound still emitted — producing `seq: 2^53` events whose `next_seq` snapshot then failed `Number.isSafeInteger` on re-restore: an engine could emit itself into an unrestorable state. Fill ids had the mirror image past `MAX_FILL_NUMBER`. Emission is now fail-closed at the bound: `beginOperation` refuses when the seq space is exhausted, `stamp()` guards the mid-operation edge, and `matchTaker` refuses fill allocation past `2^53 - 2` — the exact number `MAX_FILL_NUMBER` still folds — so emitted streams stay inside the range restore admits. Because counters only commit at operation end, a boundary refusal leaves the journal on an operation boundary: contiguous, replayable, never truncated mid-batch.
5. **Symbol-keyed fields slipped past shape validation (`instruments.mjs`, `snapshot.mjs`, `replay.mjs`).** `Object.keys` never sees symbol keys, so a symbol-keyed property on an instrument definition survived `instrumentIndex`'s strict key check, rode into `snapshot().instruments` output — where the canonical `structuredClone`/`JSON` round-trip then dropped it, violating lossless serialization — and the same gap existed on snapshot roots, order records and journal events. Definitions carrying symbol keys now fail `validInstrumentDefinition` (`instrumentIndex` refuses them), and snapshot roots, order records and fold events reject symbol keys explicitly. `snapshotPlainData`'s `structuredClone` already drops symbol keys for external input, so these checks pin the contract at the validation layer rather than relying on clone behaviour.
6. **Journal-store continuation parity diverged between backends (`postgres-journal-store.mjs`).** The memory backend enforces `seq` shape and batch-internal contiguity synchronously as `StoreError`; the postgres backend delegated everything to `append_matching_journal`, which coerces `(payload ->> 'seq')::bigint` — so a batch carrying string `"1"`, `" 1"` or `"01"` seqs passed storage (cast cleanly, contiguous) where memory refused it, and the row poisoned the journal for replay forever since `(->> 'seq')` text casts fine. The postgres `append` now enforces the local half of the rule client-side — every `seq` must be a positive safe integer contiguous inside the batch — throwing `StoreError` synchronously, identical to memory, before storage is touched. Storage-side rejections (SQLSTATE classes 22/23: data exceptions and integrity violations) are deterministic answers about the batch itself, not durability failures — they now surface as `StoreError` without latching, so a caller bug can no longer poison the durable stream *or* freeze the store. Only failures the store cannot attribute to the batch (connection loss, the latch probe in tests) still latch.

## Verified clean

- **Adversarial fold streams.** Out-of-order, duplicated and gapped `seq` values fail contiguity before anything folds; events inside a fill pair of every other type are refused (`event inside a fill pair`); fills for in-flight or already-filled makers, for orders never accepted, and maker-equals-taker pairs are refused; `resting` events for in-book or market orders are refused; `amended` events on in-flight or cancelled orders, with wrong previous values, no-op changes, or quantities at-or-below the filled amount are refused; `cancelled` on filled orders is refused; `rejected` carrying a quantity on validation-only reasons is refused; malformed `at` values fail timestamp parsing. Nothing reaches book state mid-stream: fold only touches tracked/book structures after each event validates, and `parseEngineSnapshot` is the same gate the engine's own restore path uses.
- **Crossed/emission boundaries.** `next_seq`/`next_fill`/`last_at` at and past the safe-integer bound refuse at parse; at the bound itself the engine refuses new operations atomically — `orderStatus` reports nothing, the journal gains no truncated batch, and a restarted restore still folds what is there. `fill_id` exactly `2^53 - 2` emits and folds; `2^53` fills is recorded as theoretical.
- **Namespace isolation and atomicity.** Namespaces share no rows: replaying namespace A cannot observe B's stream (pinned). `append_matching_journal` runs the whole batch under one `pg_advisory_xact_lock` with a single statement-level ordinality check — concurrent appends serialize, a rejected batch lands zero rows, and the table's append-only triggers refuse UPDATE/DELETE/TRUNCATE.
- **Failure latch.** After a genuine write failure (probe trigger in the contract test), every later `append`, `load` and `close` rethrows the same `StoreUnavailableError` — pinned. Deterministic batch rejections (caller bugs) surface as `StoreError` and do not latch — the store stays usable, also pinned.
- **Versioning and shape.** `kind`/`version` are exact matches; v1/v3/unknown fail `unsupported snapshot version`; non-object payloads, cyclic input, symbol keys and missing/extra fields fail closed before any field is read twice.
- **Clock invariants.** `last_at` is epoch-bounded and correlated to `next_seq`; a far-future `last_at` restores (the stream could legally produce it) and every later operation then fails `clock must not go backwards` atomically — pinned. `beginOperation` samples the injected clock once per operation; a throwing or backwards clock fails the call before any state is touched (wave-51 fix, re-pinned here through restore).
- **Byte-identical restore.** `JSON.stringify(live.snapshot()) === JSON.stringify(replayed.snapshot())` on the busy scenario, through the in-memory journal *and* through durable postgres rows loaded into a fresh replay; `replay → snapshot → restore → snapshot` is byte-identical too. `tracked` insertion order is a tracked-map invariant on both paths.

## Observations (recorded, not defects in this slice)

- Order-acceptance events on streams recorded before this change carry no `owner`; folding them restores `owner: undefined`, which snapshots as `owner: null`. That is the previously documented stream-data limitation, kept deliberately: post-change streams preserve owners, and a legacy stream still folds to a consistent (owner-less) engine. A snapshot taken *before* the change is the upgrade path for owner fidelity — snapshots always carried owners.
- The deferred journal commit strengthens the wave-51 atomicity story asymmetrically: the recorded stream now always lands on operation boundaries, but `tracked`/book mutations inside an operation are still not staged, so a mid-operation throw (only reachable at the ~2^53 counter boundary or via a non-compliant store) can leave live state ahead of the recorded prefix. The journal itself can never contain a half-recorded operation — replay is never poisoned.
- `MIN_EVENTS_PER_STATE` floors and the loose `next_seq`/`next_fill` bounds stay as designed: floors derived from recorded orders, not recomputed exact history — sufficient for the corruption classes hunted here.
- `snapshotPlainData` drops symbol keys during the defensive clone, so the new symbol-key checks guard the contract at the validation layer rather than being reachable from hostile external input today; the instrument-definition path *was* reachable (spread copies symbols) and is pinned.
- Raw SQL writes bypassing the store can still persist rows replay rejects (e.g. a string `seq` inside payload): the table layer enforces seq contiguity, replay is the single event-shape gate and fails closed — unchanged contract.

## Test additions

- `packages/matching-core/tests/snapshot-replay-audit.test.mjs` (46 cases): crossed-book snapshots rejected in both directions and on any instrument; `last_at`/`next_seq`/`next_fill` correlation; symbol-keyed instrument definitions; seq/fill emission bounds including the exact `MAX_FILL_NUMBER` boundary and journal integrity across a dead operation; byte-identical replay-vs-live snapshots and preserved self-trade rejection; legacy owner-less stream folding; the new adversarial fold classes (events inside fill pairs, in-flight/filled makers, double resting, market resting, amended below the filled amount, cancelled filled/amended orders, malformed `at`); memory-store continuation parity pins; far-future `last_at` failing closed.
- `packages/matching-core/tests/postgres-journal-contract.mjs` (+5 cases): string/float/internal-gap seq rejections identical to the memory backend; mid-stream rejection landing zero rows and not latching; the failure latch locking every later operation while `close` stays usable; byte-identical snapshot through durable rows.
- Repro cases fail on main and pass on this branch (14 of the in-package cases verified failing on `origin/main`); pinned-clean cases pass on both by design.
